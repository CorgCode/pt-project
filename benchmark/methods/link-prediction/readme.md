# Оценка качества эмбеддингов хостов через предсказание рёбер

## 1. Идеи и решения

### Методы оценки качества с link prediction

1. **Классический link prediction в соответсвтии с issue#40** ("контроль"). Гипотеза "похожие хосты общаются между собой". Считаем, что она заведомо ложная, поэтому метрика используется в качестве дополнительной, для сравнений. Инвертированный результат возможно даже показательней, считается за "контроль".
2. **Стабильность эмбеддинга при удалении рёбер.** Удаляем часть пар хостов, пересчитываем эмбеддинг, сравниваем с эталонным. // Предсказываем, что удаление ребер не мешает эмбеддингам быть похожими.
3. **"Размытый" link prediction**. Для хоста A берём k ближайших по эмбеддингу хостов (соседи), собираем их собеседников в прошлом (друзья), прогнозируем собеседников A в будущем: друзья / хосты, близкие к друзьям.

## 2. Реализация *

(*) код и описание этой части по большей части доверил ии-агенту, надеюсь не фатальная ошибка, допроверяю после коллоквиума.  
Структура более менее должна быть похожа на triplet_accuracy.

### Структура файлов

| Файл | Что делает |
|---|---|
| `build_edges.py` | Читает сырые CSV (без заголовка), пишет `edges.csv` с колонками `src, dst, dst_port, day, count`. |
| `common.py` | `EvalConfig`, загрузка эмбеддингов и рёбер, `EvalContext`, общий цикл `evaluate()`, бейзлайны, `lift()`. |
| `metric1.py` | Идея 1: прямой и инвертированный варианты. |
| `metric2.py` | Идея 2: создание урезанных рёбер (`reduce`) и сравнение эмбеддингов (`compare`). |
| `metric3.py` | Идея 3: размытый link prediction. |
| `README.md` | Этот документ. |

Каждый файл идей запускается из командной строки и импортируется через `run_evaluation()` (для идеи 2 — `run_stability()`).

### build_edges.py

- Потоковое чтение, отбрасывает строки с неверным форматом, вне периода, с пустым хостом или петлёй.
- `day = Time // 86400`.
- Ненаправленное ребро: пара сортируется.
- Ключ (день, пара, порт), `count` — число событий.
- Статистика пропусков выводится в stderr.

### common.py

- **EvalConfig**: пути, дни source и target, `use_dst_port`, `top_n`, `k_neighbors`, метрика (`cosine` или `euclidean`), seed. Проверяет, что окна не пересекаются.
- **Вселенная кандидатов**: все items (`(партнёр,)` или `(партнёр, порт)`) из source-окна, у которых партнёр имеет эмбеддинг.
- **Метрики по хосту**: MRR по полному ранжированию и recall@N (доля реальных целей в топ-N). Усредняются по хостам, по каждому split отдельно.
- **Coverage**: доля целевых рёбер, которые есть в кандидатах. Нужна, чтобы хорошая метрика не выглядела хорошо на подвыборке.
- **Бейзлайны** на тех же окнах и кандидатах: «как было раньше» (по частоте в source-окне), «популярные», «жребий».
- **lift** = (метод − лучший бейзлайн) / лучший бейзлайн по MRR. 0 — метод не лучше простых способов.
- **similarity_to_all**: схожесть хоста со всеми хостами (косинус или 1 / (1 + расстояние)).
- **Учёт портов** меняет вид элемента. Все порты одного партнёра получают одинаковый скор, поэтому порядок между ними алфавитный.

### metric1.py
// idea1_classic_lp

- Скор: косинус (или −евклидово расстояние). Прямой вариант ставит ближайших хостов выше, инвертированный — дальних.
- Возвращает два варианта идеи 1 и три бейзлайна.

### metric2.py
// idea2_edge_removal_stability

- **reduce**: из `edges.csv` удаляется случайная доля уникальных пар хостов (все строки пары). Пишутся `edges_r{доля}_s{seed}.csv` и список `removed_pairs_*.csv`, по которым внешний пайплайн строит эмбеддинг.
- **compare**: для уровней удаления сравниваются эмбеддинги с эталонным (уровень 0.0).
  - `overlap` (по умолчанию): доля общих k ближайших соседей по общим хостам. Выравнивания не требует.
  - `procrustes`: выравнивание поворотом, затем средний косинус строк. Требует одинаковой размерности.
- **Фоновый шум**: сравнение эталонных запусков между собой (разные seed'ы на полном графе). Без него непонятно, какая разница значима.
- Выход: среднее и разброс по уровням, фоновый шум.

### metric3.py
// idea3_neighborhood_transfer

- **Соседи**: k ближайших по эмбеддингу, веса = положительная схожесть.
- **direct**: друзья (собеседники соседей) как кандидаты, скор = сумма весов × частота контакта.
- **soft**: скор кандидата = схожесть с взвешенным центроидом эмбеддингов друзей. Друзья — это партнёры соседей; сам хост из них исключается.
