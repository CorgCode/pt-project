# Triplet Accuracy

## Описание метода

**Triplet accuracy** — метрика для проверки того, насколько хорошо эмбеддинги разделяют похожие и непохожие объекты.

**Принцип работы** — взять тройку (triplet) объектов:
1. "якорь" - рассматриваемый объект (anchor)
2. похожий на него объект (positive)
3. непохожий на него объект (negative).

Если вектор якоря ближе к положительному примеру, чем к отрицательному, то считаем, что эмбеддинг для данной тройки правильный. Метрика Triplet accuracy — это доля таких правильных троек.

**В контексте проекта:**

Под похожим объектом подразумевать объекст с одинаковой ролью (назначением), под непохожим - с другой ролью (назначением).

***

### Преимущества

1. Простота и интерпретируемость

Метрика очень понятна — либо эмбеддинг большинства троек объектов верен, либо нет.

### Недостатки

1. Игнорирование величины разницы между сравниваемыми объекстами

Если якорь хотя бы чуть-чуть ближе к positive, чем к negative, метрика считает это успехом, хотя по факту это плохой эмбеддинг.

2. Не различает «хорошо» и «едва прошло»

Бинарная оценка не показывает, насколько уверена модель. Два набора эмбеддингов могут иметь одинаковую accuracy, но совершенно разные распределения расстояний.

3. Зависит от выбора негативных примеров

Если на тестовой выборке negative-ы очень отличаются от якоря, то модель легко их отличит, и метрика будет высокой. Но на сложных кейсах может быть другая картина.

4. Не отражает качество дальнейшей кластеризации

Можно иметь выскокую метрику, но при этом хорошую кластеризацию будет сложно/невозможно провести.

### Источники Data Leakage

**Неправильное разделение triplets между train/val/test (split) в случае применения метода Triplet loss** ведет к тому, что модель будет хорошо отрабатывать на конкретных примерах, и не факт что хорошо в общем случае.

**Неразнообразный выбор negatives** (всегда из определённых классов (ролей)) ведет к тому, что модель может научиться различать только определенные классы. На новых данных (с другим распределением классов) будет работать неправильно.


## Независимые positive и negative

Для формирования независимых positive и negative предлагается использовать LLM в качестве эксперта:

1. Взять N хостов и определить их роли на основе информации о них из датасета Host Events (может быть N запросами в нейронку)
2. Составить тройки, зная роли хостов, условно:
```py
for a in hosts:
    positives = [h for h in hosts if role[h] == role[a] and h != a]
    negatives = [h for h in hosts if role[h] != role[a]]
```
