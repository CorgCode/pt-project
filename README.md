# host2vec — векторное представление хоста по сетевым взаимодействиям

MVP для проекта **PT-05** (Positive Technologies / ВШПИ МФТИ).

Сервис строит **embedding каждого хоста корпоративной сети только по сетевым
данным** (netflow в формате LANL Unified Host and Network Dataset), кластеризует
хосты, ищет для произвольного узла наиболее похожие, **объясняет почему** они
похожи и **подсвечивает аномалии переходов** хостов между кластерами во времени.
Всё завёрнуто в веб-интерфейс для SOC-оператора и в Docker.

> Гипотеза проекта: хосты с похожим назначением и характером сетевого поведения
> должны располагаться близко в embedding-пространстве, даже если их реальные
> роли заранее неизвестны. Роли используются **только** для валидации качества и
> **не попадают** в признаки/обучение.

## Данные

LANL-датасет большой (десятки ГБ) и не входит в репозиторий, поэтому есть
**синтетический генератор** (`hostembed/datagen.py`), который воспроизводит
формат netflow LANL и поведение типовых ролей сети (рабочие станции, web/db/dns/
file/mail-серверы, контроллеры домена, прокси) + **внедряет аномалии** в поздние
окна (сетевое сканирование/латеральное перемещение и смена роли хоста).

Чтобы работать на **реальном LANL**: положите файлы netflow (с заголовком или
«сырые» 11-колоночные, в т.ч. `.gz`/`.bz2`) в каталог `data/` по одному на
временно́е окно — загрузчик `hostembed/lanl_io.py` подхватит их автоматически.

Схема записи: `time, duration, src_device, dst_device, protocol, src_port,
dst_port, src_packets, dst_packets, src_bytes, dst_bytes`.

## Как это устроено

```
netflow-окна ─▶ признаки хоста ─▶ embedding (3 метода) ─▶ кластеризация
                                         │                      │
                                         ├─ поиск похожих + объяснение
                                         └─ дрейф/переходы между окнами ─▶ аномалии
                                                        ▼
                                            артефакты JSON ─▶ веб-UI (SOC)
```

1. **Признаки** (`features.py`). Для каждого хоста из потоков агрегируются
   сетевые характеристики: число/доли входящих-исходящих потоков и партнёров
   (fan-in/fan-out), объёмы и размеры пакетов, направление обмена, доли
   протоколов, энтропия потребляемых и обслуживаемых портов, индикаторы
   конкретных сервисов (53, 80, 443, 445, 88, 389, 3306, 3389, …), временны́е
   паттерны (активные часы, доля рабочего времени, концентрация по времени).

2. **Embeddings** (`embeddings.py`) — три подхода для сравнения:
   - `features` — стандартизация признаков + PCA;
   - `graph` — представление узла в графе коммуникаций (аппроксимация DeepWalk
     через PPMI + усечённое SVD, метод NetMF);
   - `combined` — конкатенация обоих.

3. **Кластеризация и поиск похожих** (`clustering.py`). KMeans с автоподбором
   числа кластеров по силуэту; поиск ближайших по косинусной близости;
   **объяснение** соседства (общие сервисы/порты, общие партнёры, совпадающие
   поведенческие признаки).

4. **Оценка качества** (`evaluation.py`):
   - **без разметки**: silhouette, Davies–Bouldin, Calinski–Harabasz, k-NN
     согласованность — по ним выбирается лучший метод;
   - **по разметке** (валидация на синтетике): ARI / NMI к истинным ролям и
     k-NN role purity (качество поиска похожих).

5. **Аномалии переходов** (`anomaly.py`). «Нормальная» структура фиксируется по
   базовому окну (эмбеддер + KMeans). Для каждого следующего окна хосты
   проецируются в то же пространство; аномальность = смещение в embedding (z-оценка
   дрейфа) + редкость перехода между кластерами по сети в целом.

## Веб-интерфейс (SOC)

- **Карта хостов** — 2D-проекция embedding-пространства, раскраска по кластерам
  или по истинным ролям. Клик по узлу → профиль, похожие хосты подсвечиваются и
  соединяются рёбрами.
- **Хост** — характеристики, характерное поведение, список похожих с процентом
  близости и **понятным объяснением** для каждого.
- **Кластеры** — размер, преобладающая роль, характерные черты.
- **Аномалии** — ранжированный список подозрительных хостов, score с разбором
  (дрейф + редкость перехода), траектория кластеров по окнам; клик открывает хост
  на карте.


кластеризацию, поиск похожих с объяснением, обнаружение внедрённых аномалий и
сквозной пайплайн.

- Проверка на реальном LANL и на трафике заказчика.
