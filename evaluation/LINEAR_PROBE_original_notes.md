# Linear / Logistic Probe

## Описание метода

**Linear probe** — метод для проверки того, насколько хорошо внешняя информация о хосте извлекается из его embedding.

**Принцип работы** — заморозить embeddings и обучить поверх них простой линейный классификатор. В нашем случае используется Logistic Regression.

Классификатор получает embedding хоста на вход и пытается предсказать внешний признак (`target`).

Если классификатор показывает высокое качество на test-выборке, значит соответствующая информация хорошо представлена в embedding и может быть извлечена линейным преобразованием.

**В контексте проекта:**

В качестве `target` следует использовать внешнее свойство или метку хоста, которая не использовалась непосредственно при построении оцениваемого embedding.

Обучение классификатора производится на `train`, а итоговая оценка — на независимом `test`.

---

### Преимущества

1. **Простота и интерпретируемость**

   Используется простой линейный классификатор, поэтому результат легко интерпретировать: если простой классификатор способен восстановить признак из embedding, этот признак линейно доступен в представлении.

2. **Не требует изменения embedding**

   Embeddings остаются замороженными. Обучается только классификатор поверх них.

3. **Позволяет сравнивать разные embedding-методы**

   При использовании одинаковых reference labels и одинакового train/test split результаты разных embeddings можно сравнивать между собой.

### Недостатки

1. **Проверяет только линейно извлекаемую информацию**

   Низкий результат не означает, что информации о target вообще нет в embedding. Информация может быть представлена нелинейно.

2. **Зависит от качества reference labels**

   Если внешние метки определены неточно, результат probe также будет неточным.

3. **Зависит от распределения классов**

   При сильном дисбалансе классов Accuracy может быть недостаточно информативной, поэтому дополнительно используется Macro F1.

4. **Не оценивает всю геометрию embedding**

   Хороший результат linear probe не означает автоматически, что embedding хорошо подходит для поиска ближайших соседей, кластеризации или других задач.

### Источники Data Leakage

**Использование test-хостов при обучении классификатора** приводит к завышению результата: классификатор должен обучаться только на `train`.

**Создание нового random split для каждого embedding** делает результаты разных методов несопоставимыми. Необходимо использовать общий `split`, заданный в reference data.

**Использование target при построении embedding** может привести к утечке информации. Внешний признак, который проверяется с помощью probe, не должен напрямую использоваться при создании оцениваемого embedding.

**Формирование reference labels на основе самого embedding** также приводит к утечке: в этом случае embedding фактически оценивается по информации, полученной из него самого.
