# Оценка эмбеддингов

Одна команда считает все метрики для эмбеддинга. Для команды есть короче —
[`scoreboard/`](../scoreboard/README.md): положил файл, получил место в таблице.

## Запуск

```bash
python -m evaluation.validate my/embeddings.csv                       # проверить формат
python -m evaluation.evaluate --embeddings my/embeddings.csv \
    --reference-dir data/reference/test --method my --output results/my.json
python -m evaluation.scoreboard --results-dir results --output results/scoreboard
```

## Формат эмбеддинга

```csv
host_id,emb_0,emb_1,emb_2
Comp001,0.12,-0.31,0.04
```

- `host_id` — строка, без повторов (`001` и `1` — разные хосты).
- `emb_*` — числа. Размерность любая.
- Нужны все хосты из `eval_hosts.csv`. Учиться можно только на объявленной
  обучающей истории; её границы и объём указываются в карточке метода.

## Метрики

В таблице все колонки сводятся в один **балл 0–100**: 0 — случайный уровень, 100 — идеал; балл — среднее геометрическое по задачам (подробно — в [`scoreboard/README.md`](../scoreboard/README.md#как-считается-score)).


| колонка в таблице | вопрос | случайный уровень |
|---|---|---|
| Соседи@10 | ближайшие соседи хоста те же, что по поведению в логах? | ≈ 10 / число хостов |
| Связь, AUC | по паре векторов видно, будут ли хосты общаться? (классификатор учится на validation) | тот же классификатор на случайных векторах той же размерности и тех же окнах |
| Новые собеседники, MRR | похожие хосты подсказывают новых собеседников? | лучший прогноз без эмбеддинга |
| Пары, AUC | хосты с общими собеседниками ближе, чем без них? | 0.5 |
| Тройки* | хост ближе к похожему, чем к непохожему? | 0.5 |
| Узнаваемость, Top-1 | тот же хост через время находится первым? | 1 / число хостов |
| Tikhon LP / transfer / soft transfer, MRR** | угадываются ли будущие собеседники по близости векторов (идея 1) или по собеседникам похожих хостов (идея 3)? | случайный порядок кандидатов |
| Зонд, accuracy | внешнее свойство хоста читается из вектора? (нужны настоящие метки) | доля частого класса |

\* Только в полном `scoreboard.csv`: тройки строятся из того же эталона, что и пары, и почти повторяют их.
Там же — связь по голому косинусу: в LANL связаны клиент и сервер, они непохожи, и косинус наказывает метод зря.

\*\* Метрики Тихона (#40, PR #65) — [`tikhon.py`](tikhon.py), как в его коде; в таблице — для сравнения, в балл не входят.
Его идея 2 — устойчивость к удалению связей: `python -m experiments.robustness`.

Эталоны строит `python -m pipeline.reference` по более позднему окну, без участия эмбеддингов.
Нет файла эталона — метрика помечается «недоступна».

## Кластеризация хостов (issue #21)

Та же команда `python -m evaluation.evaluate` дополнительно группирует хосты алгоритмом
HDBSCAN и пишет результат в `metric_details.embedding_clustering` и колонки `clustering_*`
(full CSV таблицы). Реализация — [`clustering.py`](clustering.py); параметры зафиксированы:
косинусная близость (L2-нормировка + евклидово расстояние), `min_cluster_size=5`,
`min_samples=5`. Хосты, не вошедшие ни в одну группу, получают метку `-1` (шум) —
это не «пятая роль», а просто непохожие на всех хосты.

| колонка | что показывает | как читать |
|---|---|---|
| `clustering_n_clusters` | число найденных групп | зависит от данных; не сравнивается с числом ролей |
| `clustering_noise_fraction` | доля хостов-шума | много шума — структура слабая или параметры не подходят |
| `clustering_silhouette` | насколько кластеры отделены друг от друга | −1…1, больше — лучше; только не-шумовые хосты |
| `clustering_davies_bouldin` | среднее сходство кластеров | от 0, **меньше** — лучше |
| `clustering_silhouette_random` / `clustering_davies_bouldin_random` | то же на случайном разбиении **той же формы** (те же размеры групп и доля шума) | точка отсчёта; по ней видно, есть ли в данных структура вообще |
| `clustering_silhouette_gain` / `clustering_davies_bouldin_gain` | разница с случайным разбиением | больше нуля — лучше случайного; для DB вычитание обратное |
| `clustering_ari` / `clustering_nmi` | совпадение с внешними метками, если в эталоне есть `labels.csv` с заявленным источником | 1 — полное совпадение; шум и хосты без метки исключаются |
| `clustering_ari_random` / `clustering_nmi_random`, `clustering_*_gain` | случайное разбиение и разница с ним | внешняя проверка против «уровня случая» |

Эти колонки **не входят в общий балл** (`show=False`): silhouette и Davies–Bouldin —
внутренние метрики геометрии, а не доказательство семантики. Высокий кластер-скор
не позволяет назвать группу «серверами» или «рабочими станциями» без настоящих меток.

Устойчивость во времени считается отдельно:

Функция `clustering_consistency()` из [`experiments/clustering_consistency.py`](../experiments/clustering_consistency.py)
вызывается из `experiments/run_experiment.py` автоматически и пишет `clustering_<окно>.csv/.md`
(качество разбиения по методам) и `clustering_consistency.csv/.md` (сравнение
разбиений train → test: ARI, NMI, Jaccard пар плюс дельты против случайного
эмбеддинга `random`). Обе таблицы и пояснение попадают в `report.md`.
Параметры кластеризации фиксированы и не подбираются по test-окнам.

## Обнаружение аномалий и переходов кластеров (issue #21)

`evaluation/temporal_anomaly.py` выявляет подозрительные изменения между окнами
`train → test`: хост получает метку `stable`, `changed`, `to_noise`, `from_noise`
или `noise_noise`. Кластеры разных окон сопоставляются по максимальному пересечению
общих хостов (метки HDBSCAN произвольны, поэтому сравниваются не числа, а состав).

`experiments/run_experiment.py` пишет `temporal_anomaly.csv/.md` и добавляет секцию
в отчёт. Колонки: количество/доля аномальных переходов (`n_anomalous_transitions`,
`transition_rate`), разбиение по типам и `delta_transition_rate_vs_random` — разница
с тем же расчётом для случайного эмбеддинга `random`.

Это эвристика подозрительного изменения поведения, а не доказательство атаки.
Переход может быть и легитимной сменой роли/активности; интерпретация требует
контекста.

## Как добавить метрику

1. Функция в `evaluation/<имя>.py`.
2. Если нужен новый файл эталона — построить его в `pipeline/reference.py`, только из логов.
3. Одна строка в `METRICS` в `evaluation/evaluate.py`:

   ```python
   Metric("my_metric", "Группа", "Название", ("my_reference.csv",), _my_metric, "my_number", lambda r: 0.5)
   ```

4. Тест `evaluation/test_<имя>.py`. Метрика сама попадёт в отчёт и таблицу.

## Важно

- Эталоны — приближение похожести, а не правда о ролях. Про роли говорит только зонд с настоящими метками.
- Числа с разных эталонов не сравниваются — таблица этого не даст.
- Тестовые (сгенерированные) данные проверяют только код; результаты — только на LANL.

Подробности и проверки валидности — [`docs/METHODOLOGY.md`](../docs/METHODOLOGY.md).
