# nh_F_w0.5

## Кратко

Склейка четырёх описаний хоста: профиль поведения, "с кем общается" (TF-IDF), "какими сервисами пользуется" (TF-IDF) и эмбеддинг графовой нейросети (GraphSAGE с признаками рёбер). Веса блоков подобраны на validation.

## Архитектура

Вектор = [поведение ×1, собеседники ×0.21, сервисы ×0.17, GNN ×0.26]. Каждый блок перед умножением приведён к среднему квадрату длины 1, поэтому доли блоков в векторе: поведение (профиль) 45%, собеседники (TF-IDF) 2%, сервисы (TF-IDF) 1%, GNN-эмбеддинг 3%, доп. блок (кросс-дневной) 48%. Собеседники и сервисы — логарифм числа потоков, TF-IDF по хостам, SVD (64 и 32 компонент). GNN — готовый эмбеддинг из `runs/submissions/xb_s`. Блок поведения — эталонный профиль `behavioral` из methods/baselines/temporal.py (57 чисел, стандартизован по train). Итоговый вектор сжат до 256 чисел линейной проекцией (SVD по train без вычитания среднего).

## Данные

Поля src, dst, dst_port, proto, счётчики. Словари, IDF, SVD и нейросеть обучаются на train-окне и применяются к остальным окнам с теми же осями координат.

## Обучение и подбор

Подбор весов блоков и длины SVD — Optuna (0 проб). Балл на validation по задачам: 57.8 (Behavior 84, Future links 23, Shared partners 91, Identity 63). Без GNN: 57.7 (Behavior 84, Future links 23, Shared partners 91, Identity 63). Без TF-IDF (поведение + GNN): 57.7 (Behavior 84, Future links 23, Shared partners 91, Identity 63). Только поведение: 57.6 (Behavior 84, Future links 23, Shared partners 91, Identity 63).

## Ограничения

Подбор сделан на одном validation-окне сразу после train. Блок GNN обучается отдельно и в склейке не дообучается. Направление связи в GNN не используется.
