# relation_graph_hybrid

## Кратко

**Score на test дней 14–16 — 51,2** (дни 14 / 15 / 16: 49,6 / 51,4 / 52,5). Validation выбрал вес графового блока 2: 47,17 против 44,85 у контроля без него.

Линейный графовый гибрид описывает окружение хоста отдельно по направлению и сервису связи, дополняя его собственные признаки.

Прежний протокол (test 02–04): score 54,41; дни 02 / 03 / 04: 54,77 / 54,67 / 53,79. Validation выбрал вес графового блока 2: 51,68 против 48,46 у контроля без него. Все четыре группы метрик рассчитаны с 200 bootstrap-повторениями.

## Архитектура

Поведение и TF-IDF/SVD собеседников и сервисов заимствованы из temporal_encoder. Графы строятся отдельно для четырёх наиболее частых на train сервисов «proto/dst_port» и остальных сервисов. Для каждого типа исходящие и входящие связи независимо агрегируют SVD-профиль сервисов соседей. Ещё два блока описывают соседей через общих партнёров. Веса рёбер log1p числа потоков, влияние хабов уменьшается. Блоки склеиваются с поведением и TF-IDF, затем train-PCA сжимает результат до 384 координат. CCA и нейросеть не используются.

## Данные

Общие когорта, train, validation и три test-окна scoreboard. Используются src, dst, proto, dst_port, bytes, packets, resp_bytes, resp_packets, duration, ts. Словари, TF-IDF/SVD, список типов связей и PCA фиксируются на train дня 02. В каждом следующем окне граф строится по потокам этого окна с теми же типами и преобразованиями.

## Обучение и подбор

Четыре типа сервиса выбираются по суммарному числу потоков на train. Вес графового блока выбирается из {0; 0,5; 1; 2} по validation дня 02 с учётом всех четырёх задач; 0 — контроль. Параметры и сетка сохраняются в params.json. Дни 03 и 04 используются только при итоговой оценке.

```bash
PT_COMPACT=1 OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 python scoreboard/relation_graph_hybrid.py --data /path/to/common/processed --tune --output runs/relation_graph_repro
python -m evaluation.submit scoreboard/submissions/relation_graph_hybrid
```

Все окна используют одну систему координат; посылка содержит train и три test-эмбеддинга.

## Ограничения

Популярность сервиса не задаёт реальную роль хоста. Выбран вес 2: графовый блок улучшил validation относительно нулевого веса, но может ухудшать поведенческое соседство. Результаты относятся к известным окнам benchmark.
