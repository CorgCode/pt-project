# nt__2rand38_s5

## Кратко

Склейка четырёх описаний хоста: профиль поведения, "с кем общается" (TF-IDF), "какими сервисами пользуется" (TF-IDF) и эмбеддинг графовой нейросети (GraphSAGE с признаками рёбер). Веса блоков подобраны на validation.

## Архитектура

Вектор = [поведение ×1, собеседники ×0.41, сервисы ×0.02, GNN ×0.48]. Каждый блок перед умножением приведён к среднему квадрату длины 1, поэтому доли блоков в векторе: поведение (профиль) 37%, собеседники (TF-IDF) 6%, сервисы (TF-IDF) 0%, GNN-эмбеддинг 9%, доп. блок (кросс-дневной) 48%. Собеседники и сервисы — логарифм числа потоков, TF-IDF по хостам, SVD (64 и 128 компонент). GNN — готовый эмбеддинг из `runs/submissions/xb_s`. Блок поведения — эталонный профиль `behavioral` из methods/baselines/temporal.py (57 чисел, стандартизован по train).

## Данные

Поля src, dst, dst_port, proto, счётчики. Словари, IDF, SVD и нейросеть обучаются на train-окне и применяются к остальным окнам с теми же осями координат.

## Обучение и подбор

Подбор весов блоков и длины SVD — Optuna (30 проб). Балл на validation по задачам: 58.2 (Behavior 81, Future links 24, Shared partners 92, Identity 65). Без GNN: 58.0 (Behavior 81, Future links 24, Shared partners 91, Identity 65). Без TF-IDF (поведение + GNN): 58.1 (Behavior 81, Future links 24, Shared partners 91, Identity 66). Только поведение: 57.9 (Behavior 81, Future links 23, Shared partners 91, Identity 66).

## Ограничения

Подбор сделан на одном validation-окне сразу после train. Блок GNN обучается отдельно и в склейке не дообучается. Направление связи в GNN не используется.
