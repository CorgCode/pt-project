# hybrid_tfidf

## Кратко

Лидер таблицы. Склейка трёх описаний хоста: как он себя ведёт, с кем общается и какими сервисами пользуется. Код: [`scoreboard/hybrid_tfidf.py`](../../hybrid_tfidf.py).

## Архитектура

313 чисел = `behavioral` ×2 (57) + peers (128) + services (128).
- peers: таблица «хост × собеседник» с направлением (`o:Comp1` — ходит к нему, `i:Comp1` — к нему ходят);
- services: «хост × сервис» (`u:6/443` — пользуется, `s:6/443` — обслуживает).

Для обеих: log1p числа потоков → TF-IDF (то, что есть у всех, весит меньше редкого) → нормировка строки → TruncatedSVD до 128. Перед склейкой каждая часть нормируется (среднее 0, средняя длина 1), затем умножается на вес.

## Данные

Поля `src`, `dst`, `dst_port`, `proto` и счётчики потоков. Словарь (токены хотя бы у двух хостов), IDF и SVD обучаются один раз на train и применяются к любому окну — одна система координат. Поведенческая часть — как у `behavioral`.

## Обучение и подбор

Обучение — секунды. Перебор на validation: размерность 32 / 64 / 128, вес поведения ×1…×3. Лучшее — 128 и ×2. Test открыт один раз.

## Ограничения

По Neighbors чуть хуже чистого `behavioral` (0.238 против 0.269). Размерность больше, чем у остальных. Блок peers близок к эталону Pairs (общие собеседники). Проверено на одном дне.
