# hybrid_tfidf

## Кратко

Склейка трёх описаний хоста: как он себя ведёт, с кем общается и какими сервисами пользуется. Код: [`scoreboard/hybrid_tfidf.py`](../../hybrid_tfidf.py).

## Архитектура

Три части:
- `behavioral` — поведение (57 чисел);
- peers — с кем общается: таблица «хост × собеседник» с направлением (`o:Comp1` — ходит к Comp1, `i:Comp1` — Comp1 ходит к нему);
- services — какими сервисами: «хост × сервис» (`u:6/443` — пользуется HTTPS, `s:6/443` — сам его обслуживает).

Для peers и services: логарифм числа потоков → TF-IDF (то, что есть почти у всех, весит меньше редкого) → сжатие SVD. Перед склейкой каждая часть приводится к одному масштабу и умножается на вес.

## Данные

Поля `src`, `dst`, `dst_port`, `proto` и счётчики потоков. Словари, TF-IDF и SVD обучаются один раз на train и применяются к любому окну — одни оси координат, поэтому хост хорошо узнаётся во времени.

## Обучение и подбор

Обучение — секунды. Длина SVD (64 / 128 / 256) и вес поведения (×1…×4) подбираются на validation по всем четырём задачам (`--tune`); выбранное записано в `params.json`. Test при подборе не используется.

## Ограничения

В задаче Behavior немного уступает чистому `behavioral`. Часть peers близка к эталону задачи про общих собеседников.
