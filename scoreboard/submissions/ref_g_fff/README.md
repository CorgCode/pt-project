# ref_g_fff

## Кратко

Склейка четырёх описаний хоста: профиль поведения, "с кем общается" (TF-IDF), "какими сервисами пользуется" (TF-IDF) и эмбеддинг графовой нейросети (GraphSAGE с признаками рёбер). Веса блоков подобраны на validation.

## Архитектура

Вектор = [поведение ×1, собеседники ×0.51, сервисы ×0.37, GNN ×0.32]. Каждый блок перед умножением приведён к среднему квадрату длины 1, поэтому доли блоков в векторе: поведение (профиль) 67%, собеседники (TF-IDF) 17%, сервисы (TF-IDF) 9%, GNN-эмбеддинг 7%. Собеседники и сервисы — логарифм числа потоков, TF-IDF по хостам, SVD (256 и 64 компонент). GNN — готовый эмбеддинг из `runs/submissions/gnn_new`. Блок поведения — эталонный профиль `behavioral` из methods/baselines/temporal.py (57 чисел, стандартизован по train).

## Данные

Поля src, dst, dst_port, proto, счётчики. Словари, IDF, SVD и нейросеть обучаются на train-окне и применяются к остальным окнам с теми же осями координат.

## Обучение и подбор

Подбор весов блоков и длины SVD — Optuna (30 проб). Балл на validation по задачам: 52.0 (Behavior 90, Future links 19, Shared partners 91, Identity 47). Без GNN: 51.8 (Behavior 89, Future links 19, Shared partners 93, Identity 46). Без TF-IDF (поведение + GNN): 45.5 (Behavior 99, Future links 17, Shared partners 92, Identity 28). Только поведение: 43.9 (Behavior 100, Future links 17, Shared partners 94, Identity 23).

## Ограничения

Подбор сделан на одном validation-окне сразу после train. Блок GNN обучается отдельно и в склейке не дообучается. Направление связи в GNN не используется.
