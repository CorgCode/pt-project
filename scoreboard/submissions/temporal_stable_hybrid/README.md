# temporal_stable_hybrid

## Кратко

Линейный гибрид описывает поведение хоста, его собеседников и сервисы. Дополнительная проекция ищет сочетания признаков, устойчивые между частями обучающего окна.

## Архитектура

Поведенческий профиль из `BehavioralBaseline` и направленные профили собеседников и сервисов объединяются после нормировки, рассчитанной на train. Профили собеседников и сервисов преобразуются через TF-IDF и усечённое SVD, до 128 координат каждый. Четвёртый блок — до 128 координат устойчивой проекции. Итоговые блоки взвешиваются и склеиваются без итогового PCA. Код: [`scoreboard/temporal_stable_hybrid.py`](../../temporal_stable_hybrid.py).

## Данные

Используются поля src, dst, dst_port, proto, bytes, packets и ts; длительность участвует в подготовке окон. Словари, IDF, SVD, масштабы и проекция обучаются по train, затем фиксируются для всех окон. Активность хостов внутри окна используется при построении его признаков. Для каждой когорты одно и то же окно обрабатывается целиком, поэтому выбор запрошенных хостов не меняет их координаты.

## Обучение и подбор

Train делится на четыре среза. Для активного в двух срезах хоста разность его признаков должна быть малой; пары взвешиваются корнем из числа потоков. Решается регуляризованная обобщённая задача на собственные векторы: минимизируется временная изменчивость при ограничении общей ковариации. Вес поведенческого и устойчивого блоков можно выбрать только на validation по всем четырём задачам. Вес устойчивого блока 0 включён в сетку как контроль. Параметры и вся сетка сохраняются при запуске `--tune`.

Локальный прогон на общей когорте и окнах: validation выбрал веса 2 и 2 (49,40; контроль с весом устойчивой проекции 0 — 48,50). Score по тестовым окнам дней 02, 03 и 04 — 54,40, 54,26 и 51,01; среднее — **53,23**. Векторы имеют 441 координату. Код оценки: [`experiments/temporal_stable_score.py`](../../../experiments/temporal_stable_score.py). В посылку включены train-векторы и три test-файла, чтобы CI пересчитал строку общей таблицы.

Обучение и выбор весов используют только train и validation дня 02. Дни 03 и 04 используются только для оценки. Локально имеются 6453 хоста в train-когорте и 5445, 5015, 5239 оцениваемых хостов в трёх test-окнах. Для воспроизведения с полной общей подготовкой:

```bash
PT_COMPACT=1 PT_DATA=data/scoreboard_exact/processed \
  OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 python scoreboard/temporal_stable_hybrid.py \
  --tune --validation-only --output runs/temporal_stable_repro_train
PT_COMPACT=1 OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 \
  python experiments/temporal_stable_score.py --data data/scoreboard_exact/processed \
  --model runs/temporal_stable_repro_train/model.joblib --output runs/temporal_stable_repro_score
```


## Ограничения

Устойчивость может подавить полезные изменения, а редкие хосты имеют шумные признаки. Для официального сравнения необходимы общие когорта, окна и эталоны; обучение на других окнах несопоставимо.

При подготовке исправлено различие между построением поведенческого train-профиля при fit и последующим fitted-преобразованием: теперь train, срезы и test проходят одинаковый путь. Ранние локальные результаты до исправления не используются. Финальный прогон выполнен после исправления с повторным подбором на той же validation-сетке; test уже просматривался при диагностике, поэтому это исследовательская оценка на известных окнах.
