# gnn_v11_tuned

## Кратко

Граф-нейросеть (GraphSAGE с учётом признаков рёбер) над графом «хост — хост». Хост описывается профилем из потоков (порты, протоколы, объём, активность по отрезкам окна), а вектор строится из профиля хоста и профилей его собеседников.

## Архитектура

Два слоя: сообщение от соседа строится из пары (вектор соседа, признаки ребра: log потоков, байт, пакетов, доли TCP и UDP, доля главного порта, число сервисов), сообщения усредняются с весами log(1+потоков), ослабленными для хабов (степень 0.5). Выход — вектор длины 32, нормированный до единичной длины. Направление связи не используется: инициатор в LANL определяется неточно. К вектору GNN приписана проекция профиля хоста на 32 главных компонент (PCA по train-хостам когорты, вес 2.04); итоговая длина вектора 64.

## Данные

Только NetFlow LANL, окна как в проекте. Признаки хоста (66 штук) и рёбер считаются по потокам окна одной и той же функцией (scoreboard/build_features.py), порты берутся dst_port, 20 самых частых портов — по train. Модель обучается только на train-окне; для остальных окон те же веса применяются к графу окна (общие координаты).

## Обучение и подбор

Без меток: предсказание скрытых связей (15% рёбер за эпоху, 5 случайных пар на связь, температура 0.2) плюс восстановление признаков хоста из вектора (вес 0.22908959846406926). Эпох 150, lr 0.005, hidden 64, dropout 0.1, вес связей mu 1.0, зерно 0. Параметры подобраны Optuna только по validation-эталону (файл best_params.json) (concat_k, beta, lam), test в подборе не участвовал.

## Ограничения

Не использует направление связи и точное время внутри окна (только шесть отрезков). Хабы остаются проблемой. Число собеседников у хостов вне когорты неполное. Результат зависит от зерна обучения. Склейка с профилем сближает метод с поведенческим профилем; метрика «Соседи@10» построена из похожих признаков, поэтому рост по ней частично объясняется этим. Вектор длиннее базовых 32.
