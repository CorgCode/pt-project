# future_profile_predictor

## Кратко

**Результат ниже относится к прежнему протоколу (test 02–04), а не к текущему test дней 14–16.**

Нейросеть учится предсказывать профиль хоста в следующем срезе train. Её скрытый вектор дополняет поведение, собеседников и сервисы.

Score на общих test-окнах — **56,35**; дни 02 / 03 / 04: 60,43 / 55,95 / 52,68. Validation выбрал вес нейросети 2: 56,77 против 48,46 у контроля без неё. Все четыре группы метрик рассчитаны с 200 bootstrap-повторениями.

Главный контроль на том же прежнем протоколе — temporal_encoder: 63,5 против 56,35 у этой модели (−7,15 пункта). Переиспользуются его энкодер и признаки, меняется objective; дополнительно различаются веса блоков и нормировка. Поэтому эксперимент не изолирует эффект одного objective. Вес 0 проверяет только полезность новой части внутри нашего гибрида, а не преимущество над temporal_encoder.

## Архитектура

Входные признаки и MLP-энкодер заимствованы из temporal_encoder: поведение, TF-IDF/SVD собеседников, сервисов, сочетаний «собеседник + сервис», сервисы соседей и активность. Из 128 координат декодер предсказывает признаки следующего среза; добавлен контрастивный loss с весом 0,2. При построении эмбеддинга декодер удаляется, скрытый вектор склеивается с поведением и TF-IDF-блоками, затем применяется train-PCA до 384 координат. Это новый objective, исходный temporal_encoder не обучается прогнозировать будущий профиль.

## Данные

Общая train-когорта и окна scoreboard. Используются src, dst, proto, dst_port, bytes, packets, resp_bytes, resp_packets, duration, ts. Все преобразования обучаются только на train дня 02; validation дня 02 выбирает вес нейросетевого блока. Дни 03 и 04 используются только для test. Одна модель и порядок признаков для всех окон.

## Обучение и подбор

Четыре среза train, только последовательные пары «срез → следующий срез». 20 эпох AdamW, seed 17, batch 256; loss = SmoothL1 будущего профиля + 0,2 × InfoNCE. Вес нейросетевого блока выбирается из {0; 0,5; 1; 2} по полной validation-оценке. Нулевой вес — контроль гипотезы. Параметры и кривая loss сохранены в params.json.

```bash
PT_COMPACT=1 OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 python scoreboard/future_profile_predictor.py --data /path/to/common/processed --tune --output runs/future_profile_repro
python -m evaluation.submit scoreboard/submissions/future_profile_predictor
```

Для обучения нужен torch; для оценки приложенных CSV он не требуется. Общая система координат обозначена SHARED_COORDINATES.

## Ограничения

В одном train-часе мало временных переходов. Предсказание может усреднять нестабильное поведение. Выбран вес 2: новая часть улучшила validation относительно нулевого веса, но на прежнем test уступила temporal_encoder. Все выводы относятся к фиксированным известным окнам benchmark; test не используется при подборе.
