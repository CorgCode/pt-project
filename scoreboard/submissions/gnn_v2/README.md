# gnn_v2

## Кратко

Граф-нейросеть над двудольным графом «хост — сервис» (сервис = протокол + порт назначения), по идее Xiao et al. (граф IP—порт). Вектор хоста собирается из обучаемых векторов сервисов, которыми хост пользуется и которые он предоставляет; хост–хост связей в модели нет.

## Архитектура

Один слой: сообщение от сервиса к хосту = ReLU(W [вектор сервиса (32), признаки связи: log потоков, байт и пакетов в обе стороны, роль]). Для хоста отдельно усредняются сообщения по роли «пользуется» и «предоставляет» (роль — по направлению записи: src пользуется, dst предоставляет) с весами log(1+потоков) и редкостью сервиса (idf: общеизвестные порты весят меньше). Вектор = normalize(линейная голова от ReLU(W_own·профиль хоста + W_a·[агрегат use, агрегат serve])), длина 32.

## Данные

Только NetFlow LANL, окна как в проекте. Профиль хоста (66 признаков, порты в нём не подаются на вход, чтобы не подсказывать скрытые связи при обучении) и таблица «хост — роль — сервис» считаются по потокам окна одной функцией (scoreboard/build_features.py). Словарь сервисов строится по train: анонимные порты (PortN) — один узел на протокол, сервисы реже чем у 5 хостов — узел «rare» протокола, незнакомые в другом окне — узел «unknown». Модель обучается только на train-окне; в других окнах те же веса применяются к их графу (общие координаты).

## Обучение и подбор

Без меток: каждую эпоху скрыто 15% связей хост—сервис, по вектору хоста нужно угадать скрытый сервис среди 5 случайных (по популярности^0.75, температура 0.2), плюс восстановление профиля хоста (вес 1.0); вес связей mu 1.0. Эпох 5, lr 0.005, hidden 64, dropout 0.1, зерно 0. Параметры не подбирались (значения по умолчанию).

## Ограничения

Роль сервиса определяется по направлению записи, а инициатор в LANL определяется неточно; в трети потоков порт анонимен, и сервис в них неразличим. Точное время внутри окна не используется (только шесть отрезков в профиле). Хост–хост структура не учитывается. Результат зависит от зерна обучения.
