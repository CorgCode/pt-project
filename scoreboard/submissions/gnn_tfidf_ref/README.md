# gnn_tfidf_ref

## Кратко

Склейка четырёх описаний хоста: профиль поведения, «с кем общается» (TF-IDF), «какими сервисами пользуется» (TF-IDF) и эмбеддинг графовой нейросети (GraphSAGE с признаками рёбер). Веса блоков подобраны на validation.

## Архитектура

Вектор = [поведение ×1, собеседники ×0.58, сервисы ×0.54, GNN ×0.38]. Каждый блок перед умножением приведён к среднему квадрату длины 1, поэтому доли блоков в векторе: поведение (профиль) 57%, собеседники (TF-IDF) 19%, сервисы (TF-IDF) 17%, GNN-эмбеддинг 8%. Собеседники и сервисы — логарифм числа потоков, TF-IDF по хостам, SVD (128 и 64 компонент). GNN — готовый эмбеддинг из `runs/submissions/gnn_big`.

## Данные

Только NetFlow LANL (поля src, dst, dst_port, proto, счётчики), окна как в проекте. Словари, IDF, SVD и нейросеть обучаются на train-окне и применяются к остальным окнам с теми же осями координат.

## Обучение и подбор

Подбор весов блоков и длины SVD — Optuna (27 проб), цель — балл на validation (`submit.validation_score`), test не использовался. Балл на validation по задачам: 51.3 (Behavior 86, Future links 19, Shared partners 91, Identity 47). Без GNN: 50.9 (Behavior 84, Future links 19, Shared partners 93, Identity 45). Без TF-IDF (поведение + GNN): 44.9 (Behavior 97, Future links 17, Shared partners 91, Identity 27). Только поведение: 43.7 (Behavior 98, Future links 17, Shared partners 94, Identity 23).

## Ограничения

Подбор сделан на одном validation-окне сразу после train. Блок GNN обучается отдельно и в склейке не дообучается. Направление связи в GNN не используется.
