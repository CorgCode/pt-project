# multi_xd2

## Кратко

Склейка четырёх описаний хоста: профиль поведения, "с кем общается" (TF-IDF), "какими сервисами пользуется" (TF-IDF) и эмбеддинг графовой нейросети (GraphSAGE с признаками рёбер). Веса блоков подобраны на validation.

## Архитектура

Вектор = [поведение ×1, собеседники ×0.02, сервисы ×0.15, GNN ×0.54]. Каждый блок перед умножением приведён к среднему квадрату длины 1, поэтому доли блоков в векторе: поведение (профиль) 53%, собеседники (TF-IDF) 0%, сервисы (TF-IDF) 1%, GNN-эмбеддинг 16%, доп. блок (кросс-дневной) 31%. Собеседники и сервисы — логарифм числа потоков, TF-IDF по хостам, SVD (128 и 64 компонент). GNN — готовый эмбеддинг из `runs/submissions/xb_s`. Блок поведения — эталонный профиль `behavioral` из methods/baselines/temporal.py (57 чисел, стандартизован по train).

## Данные

Поля src, dst, dst_port, proto, счётчики. Словари, IDF, SVD и нейросеть обучаются на train-окне и применяются к остальным окнам с теми же осями координат.

## Обучение и подбор

Подбор весов блоков и длины SVD — Optuna (30 проб). Балл на validation по задачам: 55.9 (Behavior 84, Future links 22, Shared partners 92, Identity 57). Без GNN: 54.8 (Behavior 85, Future links 22, Shared partners 91, Identity 52). Без TF-IDF (поведение + GNN): 55.9 (Behavior 85, Future links 22, Shared partners 92, Identity 57). Только поведение: 54.7 (Behavior 85, Future links 22, Shared partners 91, Identity 52).

## Ограничения

Подбор сделан на одном validation-окне сразу после train. Блок GNN обучается отдельно и в склейке не дообучается. Направление связи в GNN не используется.
