# deepwalk_services

## Кратко

DeepWalk на графе, где есть ещё и сервисы: хосты, которые пользуются одними и теми же сервисами, оказываются рядом.

## Архитектура

Берётся граф, где кроме хостов есть вершины-сервисы (протокол + порт, например `6/443` — HTTPS): хост соединён с сервисами, которыми пользуется (`uses`) и которые обслуживает (`serves`). Редкие сервисы выброшены. Вес ребра делится на корень из степеней концов, чтобы серверы, с которыми общаются все, не забирали все блуждания. По графу запускаются случайные блуждания: «шагаем» от хоста к его собеседникам, чаще — по рёбрам с большим числом потоков. Получаются цепочки хостов, как предложения из слов. Дальше — приём из word2vec (skip-gram): хосты, которые часто стоят рядом в цепочках, получают близкие векторы.

10 блужданий длиной 80, вектор — 32 числа.

## Данные

Поля `src`, `dst`, `dst_port`, `proto` и число потоков. Граф строится заново по каждому окну, поэтому у каждого окна свои оси координат. Чтобы проверить узнаваемость (Identity), оси test-окна поворачивают к осям train по половине хостов (выравнивание Прокруста), а проверяют на другой половине.

## Обучение и подбор

Вид графа и вес рёбер выбраны по баллу на validation (#79). Остальное — как в статье.

## Ограничения

Окна обучаются отдельно — узнаваемость слабая. Вектор длиннее (32), чем у остальных графовых методов (16).
