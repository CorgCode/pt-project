# CorgCode — рабочее место SOC

На сайте PT Network рабочее место открывается без входа. Для сохранения текущего разбора и доступа к своим наборам войдите прямо со страницы.
Из корня проекта создайте учётную запись через `python3 noomo-ui/serve.py --add-user analyst`,
затем запустите `python3 noomo-ui/serve.py` и откройте `http://127.0.0.1:8845/lab/`.
В этом режиме у каждой учётной записи отдельные сохранённые наборы. Общая локальная база
отдельного режима остаётся доступна через `python3 -m app.operator`.

Отдельное локальное приложение в визуальном стиле сайта: светлое стекло, фиолетовый акцент, Onest и Neue Machina. Дашборд `app/streamlit_app.py` остаётся инструментом оценки экспериментов; этот интерфейс предназначен для исследования устройств оператором.

## Запуск

Из корня репозитория, Python 3.10 или новее:

```bash
python3 -m app.operator
```

Открыть **http://127.0.0.1:8846/**. Дополнительные Python-пакеты, Node и подключение к Интернету для запуска не нужны. Шрифты, код и графики локальные. Остановка — `Ctrl+C`.

Другой порт и папка хранения:

```bash
python3 -m app.operator --port 8850 --data-dir ./local-workspaces
```

По умолчанию рабочие наборы, заметки, подписи, метки, статусы, список наблюдения и число групп сохраняются в `~/.corgcode/workspaces.sqlite3`. Сервер слушает только `127.0.0.1`, не публикует произвольные файлы репозитория и проверяет Host/Origin. Это личное локальное приложение, без учётных записей и совместного доступа.

## Рабочий сценарий

1. Откройте подписанный учебный пример или загрузите CSV.
2. Найдите устройство в каталоге. Карта показывает пять соседей по всем признакам, а режим «Реальные контакты» — наблюдавшийся обмен из CSV. Это разные виды отношений.
3. В «Группах» выберите группу или устройство на 2D-проекции. Число групп можно менять.
4. В «Разборе» выберите пару, сравните признаки и общие контакты. Добавьте заметку и сохраните рабочий набор. Разбор выгружается в JSON.
5. В «Изменениях» добавьте CSV более раннего окна. Текущий набор считается вторым окном. Группы сравниваются относительно центров первого окна; шкала признаков общая. Выберите строку, чтобы увидеть исходные объёмы и новые/исчезнувшие контакты.
6. В «Разборе» задайте понятную подпись, до 8 меток и статус «Не разобрано», «В работе» или «Проверено». Это ручные отметки оператора. Поиск в каталоге учитывает ID, подпись и метки. В раскрывающемся блоке доступны фильтр статуса и сортировка по имени, сходству с выбранным или активности.
7. Отметьте устройство «Под наблюдение», чтобы вернуться к нему в разделе «Важное». Оттуда можно открыть разбор, снять отметку и выгрузить читаемый список с заметками.
8. В «Изменениях» отфильтруйте устройства по ID/подписи, изменению контактов, смене группы или порогу сходства. Отдельно раскрываются ID, появившиеся и отсутствующие во втором окне. Отчёт об изменениях содержит все общие устройства независимо от фильтра.
9. Кнопка «Читаемый отчёт» сохраняет автономный HTML: заметка, статус, метки, схема текущего режима, ближайшие профили и фактические контакты. Он открывается без сервера, печать браузера позволяет сохранить PDF. JSON остаётся доступен отдельно.
10. После перезапуска откроется последний сохранённый набор. Список наборов — слева; на небольшом экране доступен кнопкой «Наборы».
11. В «Контактах» отображается весь наблюдавшийся обмен выбранного устройства. Можно найти собеседника, отсортировать по числу записей или байтам, открыть строку как новое устройство и выгрузить отфильтрованные строки CSV. Направление считается относительно выбранного устройства.

Изменения данных и заметки сохраняются кнопкой «Сохранить». Закрытие страницы с несохранёнными правками вызывает предупреждение браузера. Перед открытием другого файла, примера или сохранённого набора программа сохраняет изменённый набор. Если сохранить не получилось, переключение не выполняется.

## Форматы

Один CSV — до 3 МБ.

Трафик: обязательны `src,dst`, дополнительные `bytes,packets,dst_port,proto`. До 10 000 записей, 500 устройств. Браузер строит 20 простых признаков активности и сервисов. Это **не инференс обученной multiday_codebook_plus**.

Готовые профили: `host_id,emb_0,emb_1,...`, от 2 до 500 устройств, до 1024 координат. Нужны конечные ненулевые векторы. Можно импортировать результаты модели после приведения к этому формату. По векторам нельзя восстановить реальные соединения. Для двух периодов должны совпадать оси и размерность.

Косинус используется для поиска по всем координатам; сферический k-means — для групп, PCA-подобная степенная проекция — только для отображения. Ни номер группы, ни необычное изменение не являются ролью устройства или вердиктом об атаке. Объяснение основано на доступных признаках и контактах, а не на атрибуции нейросети.

## Проверки

```bash
python3 -m unittest app.operator.test_server
node noomo-ui/tools/check-operator.cjs
```

Для второй команды один раз установите зависимости проверок: `cd noomo-ui && npm ci`.

Серверные тесты проверяют совместимость старых наборов, валидацию статусов/меток, сохранение/обновление, повторное открытие SQLite, ограничения доступа, плохие запросы и локальные ассеты. Проверка UI использует реальную математику CSV и проверяет выбор, карту, поиск, группы, заметки, сохранение/открытие, JSON-разбор, два периода и ошибки. Отдельно проверены фильтры, наблюдение, сохранение меток, настройки групп, безопасный HTML-отчёт и фильтры изменений. Она не заменяет просмотр в браузере.

## Проверка интерфейса этой версии

Первый экран просмотрен в Chrome: бренд CorgCode, стеклянные панели, каталог, карта и инспектор отображаются. Переключение на реальные контакты подтверждено деревом доступности: один контакт service-1, 15 наблюдавшихся записей. Полный ручной проход всех экранов и мобильных размеров не подтверждён из-за нестабильного Computer Use. Функциональные сценарии перечислены в автоматической проверке выше.

Обновление рабочего цикла: сохранение статусов/меток и настроек проверено серверными тестами; клиентские сценарии проверяют поиск по меткам, наблюдение, фильтры, пустые результаты, автономный HTML без исполняемых пользовательских строк и совместимость прежних наборов. После обновления сервер перезапущен, `/api/health` сообщает `workspaceSchema: 2`. При повторном просмотре Computer Use вернул пустой снимок окна, поэтому визуальная проверка новых панелей не подтверждена.
