

### Содержание данных

Около 60 дней, 12000+ пользователях, анонимизированные хосты и действия, 17000+ компьютеров, свыше 1 млрд операций аутентификации. Каждая запись вида:

| Parameter    | Type     | Description                                                |
| ------------ | -------- | ---------------------------------------------------------- |
| `Time`       | `string` | The start time of the event in epoch time format           |
| `Duration`   | `string` | The duration of the event in seconds.                      |
| `SrcDevice`  | `string` | The device that likely initiated the event.                |
| `DstDevice`  | `string` | The receiving device.                                      |
| `Protocol`   | `string` | The protocol number.                                       |
| `SrcPort`    | `string` | The port used by the SrcDevice.                            |
| `DstPort`    | `string` | The port used by the DstDevice.                            |
| `SrcPackets` | `string` | The number of packets the SrcDevice sent during the event. |
| `DstPackets` | `string` | The number of packets the DstDevice sent during the event. |
| `SrcBytes`   | `string` | The number of bytes the SrcDevice sent during the event.   |
| `DstBytes`   | `string` | The number of bytes the DstDevice sent during the event.   |
# Подготовка данных
## 1. Признаки хоста

Из чего и как составить вектор признака каждого узла сети. За основу взято представление описанное в [статье](https://www.usenix.org/system/files/raid20-bowman.pdf)

- **Доли портов/протоколов.** Для каждого хоста считается, какую долю его трафика составляет каждый известный сервисный порт (DNS, HTTPS, SMB и т.д.), отдельно как клиента и как сервера. Признаки без вариативности (общие для всех хосты) отбрасываются заранее — они не несут информации о различиях.
- **Графовые метрики узла.** Степень (сколько партнёров), центральность (насколько узел важен для связности всей сети), эксцентриситет (длина самой длинной цепочки коммуникаций от узла). Эти метрики особенно чувствительны к цепочкам логинов/подключений через несколько хостов подряд — типичному паттерну распространения атаки по сети.
- **Энтропия портов.** Мера разнообразия: хост с одним стабильным назначением (всегда порт 445) даёт низкую энтропию Шеннона, универсальный узел (много разных портов) — высокую.
- **Временные паттерны.** Доля активности в рабочие часы, концентрация активности в конкретном часе суток.

## 2. Способы сжатия признаков в вектор (embedding)

### 2.1. Признаковый подход: PCA
Стандартизация признаков + сжатие через PCA до заданной размерности.

Стандартизация приводит признаки к общему виду: среднему 0 и стандартному отклонению 1. Так числовые теряют математическое преимущество над вероятностными.
PCA (Principal Component Analysis) - метод, строящий новые оси координат, так чтобы по максимому сохранить информацию (условно, "растяжение" данных вдоль одной оси при условиях перпендикулярности предыдущим осям). По сути поворот системы координат.
При обучении необходимо один раз обучить на датасете, а потом FIT/TRANSFORM???

**Плюс:** просто, быстро, детерминированно, легко разделить обучение/применение (fit на одних данных, transform на других), что критично для сравнения хостов в разные периоды времени.
**Минус:** учитывает только "что делает хост" (статистику), не учитывает "с кем он связан" (структуру сети); необходимо держать баланс между большим и малым количеством измерений.

Альтернатива этому — NMF (неотрицательное разложение): даёт более интерпретируемые компоненты ("роли" как неотрицательные комбинации признаков), но менее устойчиво к шуму, чем PCA.

### 2.2. Графовый подход: DeepWalk / случайные блуждания
Строится граф "хост — хост" по факту взаимодействия. С каждой вершины запускаются случайные блуждания (переходы к случайному соседу, несколько шагов подряд). Полученные последовательности используются для обучения модели по аналогии с word2vec (преобразует слово в векторное представление, которое модель "понимает" и может работать с ним дальше). Итог, вектор на вершину, отражающий её положение в структуре сети.

**Плюс:** ловит структурное сходство — два хоста могут быть похожи потому, что общаются с одними и теми же партнёрами, даже если их статистика (байты, порты) отличается.
**Минус:** не различает "что именно" передаётся между хостами (порты/объёмы) — только сам факт связи.
**Ключевой параметр:** глубина обзора графа (сколько шагов блуждания учитывать). Узкий обзор (2 шага) улавливает только близких соседей; широкий (5 шагов) — более общую структуру сети.

## 3. Поиск похожих хостов

**Базовый вариант:** k ближайших соседей по косинусному сходству векторов. Быстрый вариант, который имеет неслабую неточность.

**Более сложный вариант (link prediction):** вместо простого расстояния обучается отдельная модель, предсказывающая вероятность связи между парой хостов по их векторам (например, логистическая регрессия поверх поэлементного произведения двух embedding). Главным преимуществом может служить математическая способность характеризовать похожие узлы (чьи embedding имеют одинаково высокую вероятность схожих соседей) и выявлять аномалии (когда ребро имеет крайне низкую вероятность).

---

## 4. Объяснение похожести (explainability)

Три независимых источника объяснения:

1. Общие выделяющиеся признаки;
2. Общие сервисы/порты; 
3. Общие сетевые партнёры.

**Альтернативный, более "формальный" метод:** ошибка восстановления (reconstruction error). Признаки хоста сжимаются в очень маленькое пространство (1-3 измерения) и затем восстанавливаются обратно; то, что восстановилось плохо — по конкретным компонентам — прямо указывает, какие именно характеристики делают хост нетипичным. Метод даёт количественную, а не только описательную оценку аномальности, но менее нагляден для конечного пользователя без визуализации.

## 5. Кластеризация

**Вариант A — KMeans + подбор числа кластеров через silhouette.**
Перебираются разные значения k, для каждого считается метрика качества разбиения без разметки (насколько точки ближе к своим соседям по кластеру, чем к чужим), выбирается лучшее k.
**Ограничение:** KMeans предполагает кластеры примерно одинакового и **заданного** размера и сферической формы.

**Вариант B — [DBSCAN**](https://habr.com/ru/articles/581114/), либо его расширенная версия **HDBSCAN** + иерархическая кластеризация.
Не требует заранее знать число кластеров, находит группы произвольной формы, явно помечает "шумовые" точки, не подходящие ни под одну группу, вместо принудительного распределения по ближайшему кластеру. Иерархическая версия дополнительно даёт "дерево" вложенности кластеров — по нему можно измерить, насколько далеко (по числу уровней дерева) хост "перепрыгнул" при смене группы, что даёт более тонкую шкалу серьёзности перехода, чем просто факт "сменил/не сменил".

## 6. Оценка качества без разметки ролей

**Внутренние метрики кластеризации**.
Несколько независимых метрик качества разбиения на группы (согласованность точки со своим кластером против чужих; отношение внутригруппового разброса к межгрупповому расстоянию).

**Валидация через синтетические аномалии.** 
Описываются правила построения искусственных аномальных паттернов (например: цепочка подключений, где узел никогда не "возвращается" по тому же пути и не принимает подключения одновременно от нескольких источников). Такие паттерны перечисляются и искусственно вставляются в реальные данные. Дальше считается, какая доля внедрённых аномалий была найдена моделью (аналог полноты обнаружения) и сколько ложных срабатываний дала модель на немодифицированных данных.

## 7. Детекция дрейфа поведения / аномальных переходов во времени

**Основной принцип:** embedding и кластеризация обучаются один раз на всей истории данных (или на объединении нескольких периодов), а не заново на каждом временном окне. Это необходимо, чтобы "кластер номер 3" в разные дни означал одну и ту же группу поведения, иначе сравнение по времени лишено смысла.

**Два независимых сигнала аномальности, которые стоит комбинировать:**
1. **Дрейф вектора**. Насколько сильно физически сместилось положение хоста в пространстве embedding между периодами. Вероятностно считается устойчивым способом через медиану и медианное абсолютное отклонение.
2. **Редкость перехода между кластерами**. Не любая смена группы одинаково подозрительна. Оценивается эмпирическая частота: как часто вообще по всей сети происходит переход именно из этой группы именно в эту (мера "неожиданности" события; чем реже событие, тем больше сигнала оно несёт).
