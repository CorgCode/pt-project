Research: Анализ поведения хостов в сетевом трафике без разметки

1. Обзор методов ML для задачи

Графовые методы и embedding — основной подход. Сетевой трафик естественно моделируется как граф: узлы — хосты, рёбра — сетевые потоки между ними. Обзор GNN для обнаружения вторжений показывает, что ~78% работ на сетевых данных используют графы потоков, а ~58% работ на хостовых данных — provenance-графы.

Ключевые алгоритмы для ролей хостов:

· node2vec — универсальный embedding, учитывает как структурную роль, так и сообщества. Не требует разметки, масштабируется, может работать на edge-устройствах. Подходит для построения baseline поведения и обнаружения отклонений.
· struc2vec, RolX, role2vec, LSME — специализированы на структурных ролях. Сравнительные эксперименты показали, что Struc2Vec и RolX лучше улавливают роль узла, чем role2vec, который «не изучает структурные свойства».
· GraphSAGE — индуктивный метод, позволяет эмбеддить новые хосты без переобучения (важно для динамических сетей).
· Self-supervised learning (masked autoencoder, contrastive learning) — активно применяется для сетевой безопасности: модель учится восстанавливать нормальные паттерны коммуникаций, а аномалии выявляются по высокой ошибке реконструкции. GraphIDS достигает до 99.98% PR-AUC на NetFlow-бенчмарках.

Кластеризация и снижение размерности: HDBSCAN — для поиска групп хостов с похожим поведением (устойчив к выбросам, не требует задавать число кластеров). UMAP — для визуализации и снижения размерности embedding перед кластеризацией.

Детекция аномалий и lateral movement: современные подходы используют динамические графы и индуктивное обучение. LARES — пример unsupervised-фреймворка, который моделирует нормальное поведение хостов на графе и локализует compromised-хосты, сохраняя точность при росте сети в 5 раз и работая в 10–100 раз быстрее аналогов.

2. Датасет LANL Unified Host and Network Dataset

· Период: 90 дней, включая red team активность с 57 по 82 день (ground truth для оценки аномалий).
· Состав: host events (Windows Logging Service) + netflow логи. Анонимизирован, но сущности можно связывать между собой.
· Масштаб: ~60,000 уникальных устройств, 15,000 пользовательских аккаунтов, 26,000 имён процессов.
· Аутентификация: в среднем 3.5 млн событий в день; ключевые EventID — 4624 (успешный вход) и 4625 (неудачный).
· Netflow: ~3,740 хостов, ~1.6 млн событий (в подвыборке для тестов).

Что можно посчитать сразу: количество уникальных хостов, распределение событий по дням/часам, топ портов, топ источников/назначений, доля broadcast/multicast, доля неудачных аутентификаций. Red team активность (дни 57–82) даёт естественную метку для валидации без ручной разметки.

3. Практические выводы

1. Стартовая архитектура: граф хостов → node2vec embedding → HDBSCAN/UMAP → детекция аномалий по расстоянию до центроида кластера.
2. Для ролей хостов: добавить struc2vec или RolX как второй канал признаков — они лучше улавливают структурные роли.
3. Для динамики: использовать индуктивные методы (GraphSAGE) или self-supervised подходы, чтобы не переобучать модель при появлении новых хостов.
