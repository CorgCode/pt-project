# Остаточная направленная GNN поверх multiday_codebook

Новая модель использует **оригинальный** codebook с SHA256
`a1c4bfa15ed0c227aefd981f59b87769aece146efb232da90617e4f561b10211` и
сохраняет его 896 координат. Оба линейных выхода GNN изначально равны нулю:
`source = base_source + W_s u`, `late = base_late + W_l g`. В первом этапе
source фиксируется, во втором обучается `W_s` при фиксированном кодировщике.
Это исследовательский прототип, а не подтверждённая модель со score 90.
Числа, абляции и ограничения пилота — в [RESULTS.md](RESULTS.md).

## Граф и направления байтов

Час разделён на шесть десятиминутных частей. Для записи src=A, dst=B, bytes=100,
resp_bytes=900 A отправляет 100 и получает 900 байтов, B — наоборот. Суммы
для узлов учитывают все контакты, включая партнёров вне когорты. Узлы графа —
когорта и её прямые партнёры; рёбра между прочими хостами не представлены.
Следовательно это **не полный граф всей сети**. Петли и потоки, пересекающие
границу окна, исключаются как в подготовке проекта; байты относят к отметке
начала записи, не распределяя по её длительности.

Рёбра агрегируются по инициатору, собеседнику и хешированной паре протокола и
порта, затем сохраняются до 16 рёбер с максимальным числом потоков на узел,
направление инициирования и интервал. Возможны коллизии хеша и потеря
контекста из-за ограничения. На ребре — число потоков, байты и пакеты по
обоим направлениям, сумма длительностей и код сервиса. Более подробные
статистики длительности пока не рассчитываются. Суммы узлов считаются до
отсечения рёбер. Новая подготовка записывает также целые часовые счётчики
`hourly_bytes_int64`, проверив точность float64 до 2**53. Графы фактического
пилота созданы до добавления этого отдельного поля; их использованные суммы
хранятся в float64 и после запуска проверены на целочисленность и диапазон.

Два слоя ширины 128 отдельно агрегируют обучаемые сообщения от инициированных
и входящих связей с признаками ребра. GRU объединяет шесть представлений;
признаки часовых байтов напрямую поступают в последнюю проекцию. Состояние
GRU сбрасывается в каждом окне. Собственный ID не является признаком сети.
Для source используют усреднение графовых представлений доступных окон с
полураспадом три дня. Late строится только по своему часу. Фактический набор
source-окон пилота: 02, 10, 11, 12, не все данные дней 02–12.

## Пилот и следующее исследование

1. `zero_check` проверяет тождественность векторов после сохранения и считает
   пять метрик дня 13 при нулевой поправке.
2. `train_identity` учит позднюю поправку по дням 10–12 и контрастивной цели
   с stop-gradient Procrustes. Разбиение calibration/evaluation внутри батча
   приближённое и не заменяет отложенный по времени тест. Кодбук уже обучался
   на этих днях, поэтому обучение in-sample для основы, не rolling-prefix.
3. `train_donors` фиксирует графовый кодировщик и обучает `W_s`, используя
   исторические замены доноров, исходные source02 частоты, положительные
   cosine-веса и midrank. Метки берутся только из дней 10–12; активная когорта
   исторического целевого окна моделирует вход оценщика. Для задачи source
   векторы образуют общую геометрию. Небольшой список замен и его награды —
   приближение; равенства и вычислительная точность могут отличаться от полного
   оценщика. `evaluate_donors` повторно считает все метрики по CSV.
4. Совместный этап, длинное обучение и честные переобучения всех компонентов
   на нескольких исторических префиксах **не проводились**. На основе текущих
   результатов оснований заявлять переносимый выигрыш нет.

## Повторение

Задайте переменные `PT_DATA` (каталог `PT_PROJECT_ML`), `PT_RUN` (новый
каталог вне Git) и `PT_DEV_REFERENCE` (локальный эталон дня 13). Нужны PyTorch,
NumPy, pandas, SciPy, scikit-learn, joblib и оригинальный checkpoint; для
распаковки старых имён pickle нужен архив `/private/tmp/pt-original-multiday`
или путь `--archive` к нему. Результаты и большие веса не входят в Git.

```sh
python -m experiments.codebook_directed_gnn.prepare --data "$PT_DATA" --output "$PT_RUN/windows" --part train
python -m experiments.codebook_directed_gnn.prepare --data "$PT_DATA" --output "$PT_RUN/windows" --part dev
python -m experiments.codebook_directed_gnn.zero_check --data "$PT_DATA" --reference "$PT_DEV_REFERENCE" --output "$PT_RUN/zero"
python -m experiments.codebook_directed_gnn.train_identity --data "$PT_DATA" --windows "$PT_RUN/windows" --output "$PT_RUN/train" --steps 12 --batch 256
python -m experiments.codebook_directed_gnn.evaluate_identity --data "$PT_DATA" --windows "$PT_RUN/windows" --training "$PT_RUN/train" --reference "$PT_DEV_REFERENCE" --zero "$PT_RUN/zero" --output "$PT_RUN/dev"
python -m experiments.codebook_directed_gnn.train_donors --data "$PT_DATA" --windows "$PT_RUN/windows" --training "$PT_RUN/train" --zero "$PT_RUN/zero" --output "$PT_RUN/donors" --steps 6 --batch 4
python -m experiments.codebook_directed_gnn.evaluate_donors --data "$PT_DATA" --training "$PT_RUN/donors" --late "$PT_RUN/dev/late.csv" --reference "$PT_DEV_REFERENCE" --output "$PT_RUN/dev_donors"
```

Для контрольных запусков добавить `--no-graph` или `--directionless-bytes` в
`train_identity` и использовать отдельные папки. Второй вариант усредняет
два направления байтов для узлов и рёбер, сохраняя их суммарный объём; типы
инициирования соединения и прочие признаки остаются различимыми. Окна 14–16
не используются этими командами. Их нельзя назвать независимым тестом:
в проекте они уже исследовались.
