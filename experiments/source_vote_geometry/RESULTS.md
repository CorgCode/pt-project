# Общая геометрия для донорского голосования: пилот

**Пилот повышает New partners MRR на development-дне 13, но общий score
снижается во всех трёх запусках.** Условие продолжения — прирост MRR на 0,04
с контролем остальных метрик — не выполнено. Late-адаптер не обучался.
Это результат по одному уже изученному окну, а не строка общей таблицы и
не оценка на независимом периоде.

## Постановка

Исходная точка — восстановленный multiday_codebook: одна матрица source
6453 × 896, без доступной добавочной головы plus. Source02 — день 02,
11:00–12:00; число контактов в исходной sparse-матрице проверено по каждой
строке source в эталоне дня 13. Веса основы обучены на днях 02–12.

Новая модель обучает независимую 896-мерную поправку для каждого хоста;
косинусы вычисляются после нормировки суммы исходного вектора и поправки.
Для каждого обучающего эпизода 03–12 выбирается активная когорта всего
окна, а не только батча. Цели — новые относительно source02 собеседники
этого окна. День 13 используется только для оценки и остаётся development.
Сама основа видела дни 03–12, поэтому это не rolling-prefix проверка.

Прямой проход выбирает настоящие top-10 и считает их голоса как сумму
неотрицательных косинусов, умноженных на исходные частоты контактов.
Straight-through передаёт приблизительный градиент через сглаженный top-10.
Суррогат минимизирует log сглаженного ранга лучшего положительного
партнёра; добавлен штраф размера поправки. Масштаб голосов каждого запроса
делится на его максимум без градиента. Это **не** точный градиент MRR;
процедура отличается от предложенной reciprocal-rank функции потерь.
Отдельной функции сохранения парных сходств пока нет: есть только штраф
на норму поправки. Этот пилот проверяет ограниченный вариант гипотезы.

Три seed: 17, 29 и 41, начальные поправки нулевые; каждый запуск — 100 шагов,
батч 16 запросов, Adam lr 0,002, температура top-k 0,03, вес штрафа 0,5.
На каждом шаге по кругу используется одно из десяти исторических окон.
Один полный source-набор фиксируется сразу для всех окон. Промежуточные
точные MRR записаны на шагах 0, 50 и 100; полная оценка для всех трёх seed
выполнена на одинаковом шаге 100. Выбора по тестовым дням нет.

## Точный development, день 13

Для всех строк: 1757 активных хостов, 1323 с учитываемыми новыми
партнёрами. Identity — оригинальный late-адаптер, официальное выравнивание
Procrustes, seed 0. Обучаемый Links-probe использует отдельный эталон дня 02
12:00–12:30, как в локальной процедуре восстановления основы. Score —
локальный score одного development-окна на пяти метриках; не среднее дней
14–16. Links рассчитан локальным ограниченным по памяти fit, как в
`experiments/masked_multiday/common/evaluate.py`.

Здесь Neighbors — сырое значение. Разница MRR по seed соответственно
+0,01408, +0,02272 и +0,01765; разница score −1,387, −1,318 и −0,503.
Это три выборки обучения, но всё ещё только один временной development;
нельзя заключать о переносе на другие дни. Наблюдаемые ухудшения Identity
относятся к **старому адаптеру** и не устанавливают, что адаптер к новой
геометрии невозможно обучить. Тем не менее заранее установленный фильтр
перехода к нему не выполнен.

## Ограничения и воспроизведение

- Файлы checkpoint хранятся в `runs/source_vote_geometry_0{1,2,3}/` как
  source-матрицы шагов 0, 50, 100; это пилотные артефакты, не посылка.
- Никакие метрики тестовых окон 14–16 здесь не вычислялись. Результат
  дня 13 изучен при подборе и не является независимой проверкой.
- История является обучающей для основы; честные временные fold требуют
  заново обучать основу и адаптер с соответствующими cutoff.
- Нет доказательства потолка возможного score или бессмысленности любых
  методов обучения через голосование. Проверена одна настройка суррогата.
- Проверка двух синтетических случаев: точное жёсткое голосование в прямом
  проходе, конечность градиента, исключение старых контактов и своего ID.
