# Temporal GATv2: направленная графовая модель с байтами

Исследовательский метод с двумя слоями edge-aware GATv2, отдельными
входящими/исходящими сообщениями и двумя временными Transformer-блоками.
**Score 90 не гарантирован.** Статус и фактические результаты запуска — в
`RESULTS.md`; development и benchmark нельзя объявлять независимыми, поскольку
эти окна ранее изучались.

## Архитектура и данные

В каждом часовом окне строятся 12 пятиминутных графов. Для строки `src → dst`
исходящие/входящие байты src — `bytes`/`resp_bytes`, а для dst — наоборот.
Пакеты считаются аналогично. Суммы на узлах подсчитываются **до** ограничения
соседей. Запись относится ко временному интервалу по `ts`; её байты не
распределяются по времени внутри потока. Self-flow и потоки, пересекающие
границу часа, исключены по правилам подготовки.

Граф содержит все хосты когорты и их наблюдаемых прямых партнёров, в том
числе вне когорты. Суммы для включённых узлов учитывают и остальные контакты,
но рёбра строятся между включёнными узлами. Не связанные с когортой узлы вне
этого графа не моделируются; это ограниченная локальная область, а не полный
граф сети. По каждому узлу, направлению и пятиминутному интервалу сохраняются
до 16 рёбер с наибольшим числом потоков после точной агрегации. Такая отсечка
сделана одинаково для обучения и inference; она может терять часть контекста.

GATv2 вычисляет динамический вес ребра после нелинейного объединения
преобразований **запроса, соседа и признаков ребра**. Направления имеют
раздельные обучаемые параметры. Затем Transformer объединяет 12 частей часа;
второй Transformer объединяет разрешённые исторические окна с маской и
относительным временем. Дополнительная проекция получает хешированные
направленные контакты партнёров. Собственный ID узла используется для
построения графа и обучающих соответствий, но не является входным признаком
сети; наблюдаемые ID партнёров участвуют в хешированных контактных признаках.
Нейросеть выдаёт один L2-нормированный 512-мерный embedding на хост.

Временная синусоидальная кодировка вдохновлена [TGAT](https://arxiv.org/abs/2002.07962),
но здесь используется кодировка позиций агрегированных интервалов; это не
полное воспроизведение TGAT. GATv2 основан на [работе Brody et al.](https://arxiv.org/abs/2105.14491)
и реализован средствами обычного PyTorch без зависимости от PyG.

## Обучение

`train.py` использует один общий encoder. Доступные обучающие эпизоды:
source 02+10 → target11, source 02+10 → target12, source 02+10+11 → target12.
Словари из тестовых окон не обучаются. В этом пилоте использованы окна 02,
10, 11, 12; это **не** полный train дней 02–12 и не эксперимент со скользящим
12-дневным окном. Окна 13 и 14–16 не читаются в обучении.
Веса сети инициализируются случайно: это самостоятельная модель, а не
дообученный checkpoint Similarity Graph или многодневного codebook.

Потери:

- Identity с отдельным случайным calibration/evaluation и stop-gradient
  Procrustes, плюс прямая контрастивная компонента. Размер calibration
  ограничен батчем; при выходе 512 его ранг может быть существенно ниже,
  чем у официального оценщика.
- Source02-голосование: жёсткий top-10 в прямом проходе, положительный cosine
  и исходные частоты контактов; сигмоида и straight-through дают приближённый
  градиент. При равенстве сходств выбор `torch.topk` может отличаться от
  оценщика. Обучающий rank-loss — суррогат, а не официальный MRR.
- BCE прогнозирования исторических связей, приближение поведенческих и
  контактных отношений и восстановление замаскированных входящих/исходящих
  байтов. Байтовые признаки рёбер, инцидентных замаскированному хосту, тоже
  скрываются от модели.

Сеть общая для всех эпизодов и обучается по всей train-истории. Поэтому эти
эпизоды не являются независимыми rolling-prefix тестами. Поддерживаются
`--warmup-steps`, `--disable-graph`, `--disable-bytes`, `--disable-vote`;
использованные настройки конкретного запуска всегда фиксируются в его
`protocol.json`. Контроль без графа сохраняет собственные признаки и MLP;
контроль без байтов удаляет соответствующие узловые и рёберные признаки.
Запросы обучающего batch выбираются среди активных хостов, имеющих хотя бы
одного допустимого нового партнёра. Поэтому Identity и остальные потери
обучаются на этом подмножестве, а не на всех активных хостах. Это возможный
источник смещения и существенное отличие от полного протокола оценки.

`evaluate_dev.py` кодирует source из истории 02+10+11+12 и late из одного
часа дня 13, затем рассчитывает все пять метрик с локальной нормировкой.
Он принимает только завершённый checkpoint с проверенным SHA. Перед
подготовкой benchmark-окон `prepare_windows --part benchmark` требует
сохранённый development selection; тестовые потоки не нужны для обучения.

## Реализация и ограничения

Выбор соседей строится с известными ограничениями: частичная локальная
область графа и cap 16. Хеш контактных и сервисных токенов может иметь
коллизии. Сигмоидный топ-k и rank-loss могут улучшаться без роста настоящего
MRR; качество нужно измерять жёстким `evaluation.partners`. Предсказание
связей обучающей головой не подменяет официальный learned-Links probe.

Дополнительные требования полного исследования — rolling-prefix с
переобучением всех весов, несколько seed, сравнения без графовых сообщений,
без байтов и без донорной потери, а также новый закрытый период. По одному
development-окну нельзя обоснованно заявлять ожидаемый score 90.

Большие графы, данные и checkpoint не входят в Git. Общие пути к данным и
артефактам передаются аргументами команд; `prepare_windows.py`, `train.py`,
`evaluate_dev.py` показывают допустимый временной порядок.

Пример пилота из корня репозитория (укажите пути к данным, новому каталогу
запуска и development-эталону):

```sh
python -m experiments.temporal_gatv2.prepare_windows --data "$PT_DATA" --output "$PT_RUN/windows" --part train
python -m experiments.temporal_gatv2.prepare_windows --data "$PT_DATA" --output "$PT_RUN/windows" --part development
python -m experiments.temporal_gatv2.train --data "$PT_DATA" --windows "$PT_RUN/windows" --output "$PT_RUN/model" --steps 30 --width 256 --batch 64 --seed 17
python -m experiments.temporal_gatv2.evaluate_dev --data "$PT_DATA" --windows "$PT_RUN/windows" --training "$PT_RUN/model" --reference "$PT_DEV_REFERENCE" --output "$PT_RUN/dev"
```

Каталоги `model` и `dev` должны отсутствовать до запуска. `PT_DATA` содержит
`late_test`, `fingerprint_transfer`, `fingerprint_aligned`,
`fingerprint_memory`, `fingerprint_expanded`, `fingerprint_recent` и
`fingerprint_codebook_recent`; development-эталон содержит
`eval_hosts.csv` и остальные файлы проекта. Для двухэтапного варианта задайте
`--warmup-steps N`: первые N шагов выполняются без донорной потери. Это
отдельный эксперимент, не настройка опубликованного пилота.
