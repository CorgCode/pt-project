# Temporal Graph Mixer: локальный эксперимент

Модель реализована с нуля, обучена и проверена по всем пяти метрикам PT-05. **Выбранная на development версия дала 61,7397 по среднему score дней 14–16. Цели >70 и >90 не достигнуты.** Это локальный расчёт по протоколу таблицы, не новая опубликованная строка рейтинга.

## Что именно проверяли

Идея: четыре блока по 128 координат — собственное поведение, конкретные собеседники, сервисы и графовое окружение. Направленная диффузия по числу потоков и объёмам переданных байтов извлекает контекст на одном и двух шагах без GNN. Графовый профиль сжимается после диффузии. Временной MLP-Mixer обрабатывает четыре последовательных четверти часа, учится узнавать хост между днями, восстанавливать признаки и прогнозировать следующие 15/30/45 минут. Итоговый вектор имеет 512 координат.

Это самостоятельная реализация, а не добавка к `multiday_codebook_plus`. Чужие веса/codebook не использованы. Подробности признаков, функций потерь, контроля причинности и команды — в [README.md](README.md).

Есть два варианта source: исходное окно 02 и фиксированный профиль разрешённой истории. В последнем собственные признаки остаются от 02, а обученные stable/dynamic-компоненты усредняются по активным историческим наблюдениям с полураспадом три дня. Один source используется для всех поздних окон.

Некоторые старые ссылки в данных указывали на отключённый диск; конфиг использует существующие локальные файлы, исходные данные не менялись.

Для каждого benchmark-окна проверены границы source/target, активная когорта, SHA эталонных CSV и полные частоты контактов против `partners.csv`. Применены потолки соответствующего канонического окна. Для дня 13 используется отдельная локальная калибровка. Links probe: штатные pair-признаки, StandardScaler, LogisticRegression C=1, validation-эталон дня 02; случайный контроль пересчитан для 512 координат. Для экономии RAM признаки материализуются в memmap; соответствие штатному оценщику проверено тестами. Identity — штатный Procrustes с seed 0. Прямое узнавание без выравнивания записано отдельно в JSON.

Использован снимок `70347a3`. На момент проверки файлы `evaluation/scoreboard.py`, `identity.py`, `partners.py`, `future_links.py` совпадали с `main` на `4e03376` по Git blob SHA. Это не утверждение, что весь репозиторий между коммитами одинаков.

**Дни 13–16 ранее изучались командой. Версия 2 разработана после просмотра результатов версии 1 на 14–16. Поэтому обе оценки диагностические, независимого закрытого holdout здесь нет.** Внутри каждого прогона checkpoint/source фиксировались до его benchmark-оценки, выбор кандидата выполнялся по дню 13. Это не устраняет влияние предыдущих экспериментов.

## Recipe и выбор

Один seed: 17. Сначала по 600 шагов предобучения для `no_graph` и `graph`. Затем отдельный `adapted`-контроль: 200 шагов приближения штатного голосования за новых партнёров с сохранением геометрии. Дополнительно исходные `no_graph` и `graph` проходят по 600 шагов full-gallery identity supervision; обучаемые class-proxy используются только как цель и в inference не входят.

На development сравниваются 17 конфигураций: простая склейка, исходные/исторические source, graph/no_graph, voting adaptation, full-gallery обучение и небольшая сетка весов блоков. Выбор — максимальный полный score при raw Neighbors@10 не ниже 95% простой склейки. Это фактически реализованный guard, а не универсальный порог 0,222 для всех окон. У выбранной модели на development Neighbors@10 = **0,253785**.

Победил `no_graph_global_w2`: веса own/stable/dynamic = **1 / 1 / 1**, historical source, размерность 512. Его development-score **58,1533**. Графовый вариант того же recipe остался обязательным парным контролем. Benchmark не использовался для переключения между ними.

## Первая версия и исправление признаков

У первой версии own-блок имел 146 входов и номинальные 128 PCA-координат. По порогу дисперсии `1e-8 × max` информативных компонент оказалось 24. Во второй версии добавлены распределение сервисов и сводки разнообразия: 282 входа, все 128 сохранённых компонент превышают этот порог; объяснено 98,35% train-дисперсии. Это увеличение информации, а не гарантия улучшения задачи.

| Версия, выбор только по своему development | Development | 14 | 15 | 16 | Среднее |
|---|---:|---:|---:|---:|---:|
| v1, no_graph_global_w1 | 57,8402 | 59,6724 | 60,5167 | 65,8138 | 62,0010 |
| v2, no_graph_global_w2 | **58,1533** | 59,9336 | 60,5175 | 64,7680 | 61,7397 |

Улучшение development не перенеслось в средний benchmark-score. Артефакты обеих версий сохранены. В handoff используется v2 как выбор по development, а значение 62,0010 не выдаётся за результат v2.

Дополнительная диагностика на development: прямой поиск по историческим профилям без собственного ID дал Top-1 по всем 6453 классам 0,3734 для peers, 0,4200 для peers+services и 0,4257 для own+peers+services. Это другая задача, чем официальный Top-1 после Procrustes; её нельзя напрямую подставлять в score. Поиск не добавлен к финальному encoder.

## Что эксперимент установил

- Временное обучение вместе с историческим source и весами блоков обошло простую склейку примерно на 6,45 балла. Только исходное предобучение её не обошло.
- Фиксированная графовая диффузия работоспособна, но убедительного прироста в этой конфигурации нет.
- Partner-loss с hard top-10 forward и soft backward не обеспечил выигрыша полного score. Это приближение MRR, а не успешная оптимизация самого дискретного показателя.
- Основные ненасыщенные метрики — новые партнёры и узнавание. Высокие Links/Shared partners AUC сами по себе не довели результат до 70.
- Простое расширение собственного блока улучшило development, но не benchmark. Увеличение числа параметров/координат не является доказанным способом получить 90.

Не выполнены пять seed, новый закрытый период и строгий host-disjoint эксперимент. Архитектура принимает новые query-хосты, но измеренная точность относится к известной когорте. Двенадцатидневный скользящий контекст не реализован: в этом бюджете всего 11 часов разных дней. История из полных суток, явная temporal Links-цель и отдельный прогноз партнёров могут стать другими экспериментами; их эффект здесь не измерен.

## Артефакты и передача

Все перечисленные ниже пути относительно корня локального репозитория; это содержимое `runs`, оно не коммитится:

- `runs/temporal_graph_mixer_01/v2/benchmark/report.json` — все пять метрик, детали, контроли и среднее.
- `runs/temporal_graph_mixer_01/v2/development/frozen_selection.json` — 17 результатов и зафиксированный выбор.
- `runs/temporal_graph_mixer_01/v2/final_trained/` — checkpoint всех конфигураций, train-тензоры, transformations, журналы и provenance.
- `runs/temporal_graph_mixer_01/v2/bundle/` — компактная переносимая выбранная модель: preprocessing, checkpoint, фиксированный source, selection/training manifests, SHA и версии библиотек. Сырых потоков в bundle нет.
- `runs/temporal_graph_mixer_01/v2/replay_day13.csv` — повторный inference из одного bundle; его координаты точно совпадают с оценённым CSV.
- `runs/temporal_graph_mixer_01/v2/verification.json` — проверка повторяемости, SHA, размерности, формата и единого source.
- `runs/temporal_graph_mixer_01/v2/full_suite_final.log` — 488 passed, 6 skipped; `targeted_final.log` — 15 passed.
- `runs/temporal_graph_mixer_01/benchmark01/report.json` и `bundle/` — сохранённая v1.

Формат CSV: `host_id,emb_0,...,emb_511`; 6453 строки, единые координаты. Checkpoint содержит параметры общей сети, class-proxy отсутствует. Для late inference нужен настоящий NetFlow, одних эталонов недостаточно. Пример CLI и зависимости приведены в README; версии sklearn/joblib для сохранённых transforms надо сверять с manifest.

В Git добавлены только новый код, тесты, пример конфига и отчёт. Таблица и существующие данные не изменены. Для официальной посылки понадобятся отдельная карточка и экспорт source/трёх late CSV в актуальную структуру scoreboard.
