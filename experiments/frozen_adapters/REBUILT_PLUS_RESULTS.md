# Результат самостоятельного обучения на локальных днях 02–04

**Весов теперь достаточно для работы без исходного checkpoint лидера.** Обучена самостоятельная реконструкция `rebuilt_plus` по опубликованной схеме, затем проверены Identity и поправка соседей. Архитектура и отличия от оригинала — [REBUILT_PLUS.md](REBUILT_PLUS.md). Это не исходный `multiday_codebook_plus` с опубликованными 70,04.

## Данные и разделение

| Назначение | День | Интервал |
|---|---|---|
| Train | 02 | [126000,129600) |
| Train | 03 | [212400,216000) |

Обучение использует **три часовых окна из трёх дней**, не три полных суток. Train, development и test не пересекаются; потоки, пересекающие конец окна, исключены. День 04 есть в train, поэтому test — отложенный час, не целиком отложенный день. Эти исторические данные уже встречались в исследованиях: новый независимый закрытый test не заявляется.

Когорта source — 6453 хоста, выбрана по исходной подготовке дня 02. На development активны 5143, на test — 5165, порог >=300 событий. Все сравнения внутри окна используют одинаковую когорту и эталоны; классы настоящих ролей не предполагаются. Дни 14–16 в обучение/подбор этого опыта не входят. Links-probe обучается на каноническом validation дня 02 с тем же source-часом.

Потолок сырого Neighbors@10 рассчитан через persistence исходного поведенческого профиля: 0,14536263 на development и 0,13878025 на test. Применены все пять обязательных метрик и штатное геометрическое объединение четырёх групп. **Это полный локальный score, не официальное место общей таблицы.** С прежним диагностическим score 57,63 на другом часе дня 04 сравнивать его напрямую также нельзя.

## Выбор только на development

| Конфигурация | Score |
|---|---:|
| Штатный адаптер: лучший из blend 0/0,5/1 | 62,63097 |
| Только новый Identity | **64,39837** |
| Поправка соседей 0,1 + заново обученный Identity | 64,04006 |
| Поправка соседей 0,2 + заново обученный Identity | 63,29847 |

Штатный blend — 1, то есть Ridge. Новый Identity — нормированная смесь 50% штатного прогноза и 50% поиска по устойчивым редким контактам, температура 0,02. Штатный адаптер участвовал в выборе наравне с новыми вариантами. Чистый новый Ridge и gate не выиграли.

Для каждого ненулевого изменения source Identity **обучен заново под конечные координаты**. Обе поправки прошли ограничение потери сырого Neighbors <=5%, но снизили полный score. Поэтому до test зафиксирована сила **0**: итоговый метод — Identity-only. OOF gate использует целые более ранние train-дни, условно на замороженной основе, обученной на всей разрешённой истории; это не rolling-переобучение самой основы.

## Более поздний test дня 04

| Конфигурация | Score | Identity Top-1 | New partners MRR |
|---|---:|---:|---:|
| Восстановленный plus, штатный адаптер | 61,06339 | 0,42293 | 0,39776 |
| **Восстановленный plus + выбранный Identity** | **63,66312** | **0,49961** | 0,39776 |

Прирост score — **2,59973**, Identity — **7,67 процентного пункта**. Source не изменён: Neighbors@10 = 0,09492740, Links AUC = 0,99066520, New partners MRR = 0,39776084, Shared partners AUC = 0,93111561 совпадают у двух вариантов. Для полноты runner сохранил четыре конфигурации; поскольку выбран вес соседей 0, neighbors-only совпадает с baseline, combined — с Identity-only. Ненулевой поправке улучшение test не приписывается.

95% интервалы Identity, штатный host-bootstrap из 100 повторов: baseline [0,40181;0,44056], новый вариант [0,47583;0,51496]. Это интервалы на одном историческом окне; они не доказывают перенос на новые дни или на исходные веса лидера. **90 баллов не получено.**

## Где теряется прогноз новых контактов

На одних и тех же 128 допустимых запросах test, seed=31:

| Способ | MRR |
|---|---:|
| Популярность | 0,06084 |
| Голосование исходных source-векторов | 0,39599 |
| Oracle принудительных замен top-10 | 0,60062 |
| Собственная история контактов | 0,66612 |
| Обучаемый прямой прогноз | 0,69421 |
| Фиксированная временная эвристика | **0,73241** |

Для новых контактов исключены контакты source дня 02; контакт из дня 03/раннего дня 04 остаётся разрешённой исторической подсказкой. История заканчивается до test. Прямой прогноз лучше голосования: парный bootstrap-интервал разности [0,21552;0,38210], но уступает простой эвристике.

Oracle использует известные ответы **только после фиксации модели для диагностики**, пробует ограниченный набор замен с настоящими частотами и midrank-ничьими. Это не обученный результат и не верхняя граница всех возможных десяток. Наличие улучшения 0,396 → 0,601 показывает полезные доступные замены; обученный вектор их пока не воспроизвёл. Главный следующий опыт — более точный перенос полезных десяток в геометрию с полным score и переобучением Identity, сохраняя эвристику обязательным контролем.

## Артефакты и проверки

Веса и отчёты локально: `runs/rebuilt_plus_local/`. В Git только код, пример конфигурации, тесты и документы. `train01` — первоначальный fit, `train02` — повтор после поддержки отдельного canonical source-окна. Их source CSV совпадают побайтно, SHA-256 `b9b2de34dd857eb93f13399950d0d1d865189ac535f0a44b6c38acc3988e5c1d`.

`experiment02` хранит результаты выбора, эталоны и неизменённый pre-test freeze. Для передачи использовать **`handoff/selected.joblib` и `handoff/source.csv`**. У первоначального wrapper исправлена ссылка на класс `__main__`; `handoff/migration.json` связывает исходный и переносимый checkpoint по SHA. Это изменение сериализации после диагностики, без fit/подбора/изменения тензоров. Проверены source, codebook, обе нейросетевые головы, граф, Ridge и sparse-профили; вывод inference сравнивается с ранее рассчитанным test CSV. В итоговом коде wrapper определён в импортируемом модуле, проблема не воспроизводится.

Полный набор после поддержки canonical source: 491 passed, 6 skipped. Последующие проверки модулей, включая загрузку checkpoint в отдельном процессе: 19 passed. Отдельно проверен запуск тестов без необязательного torch: стандартный CI не требует установки нейросетевого стека. Готовые source/late CSV проходят штатную проверку формата, 6453×1024.
