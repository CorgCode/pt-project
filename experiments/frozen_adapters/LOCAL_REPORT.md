Реальных source-векторов/checkpoint `multiday_codebook_plus` и полной истории здесь нет. Код допускает их передачу без изменения алгоритма, но улучшение score 70,04 не заявляется.

## Identity при неизменном source

Validation выбрал редкие устойчивые контакты, температура 0,02, top-20: официальный Top-1 0,46334 против 0,36490 у исходного замороженного encoder. Переобученный Ridge — 0,21981, gate — 0,39705. Исходный Ridge-адаптер настоящего plus недоступен: его сравнение этим опытом не заменяется.

| Модель | Official Top-1: source→late, Procrustes, половина галереи | Прямой source→late, вся активная галерея | Прямой late→source, вся активная галерея |
|---|---:|---:|---:|
| Исходный замороженный encoder | 0,32846 | 0,26793 | 0,27939 |
| Переобученный Ridge | 0,18182 | 0,14345 | 0,10512 |
| Редкие устойчивые контакты, выбранный вариант | **0,40721** | **0,38364** | **0,35448** |
| Обучаемый gate | 0,33360 | 0,30192 | 0,28077 |

Официальный Top-1 вырос на 7,88 процентного пункта. Прямая узнаваемость late→source тоже выросла. Галерея подгрупп одна — все 5061 активных хостов. Порог активности 568 событий определён на train: для малой активности late→source 0,20055 → 0,26720; для большой 0,35997 → 0,44367.

SHA входного source и его выходной побайтной копии совпали. Поэтому первые три группы benchmark при тех же эталонах сохраняются по устройству оценки. Общий score для этого локального окна не рассчитывался: matching полный набор эталонов с данным source не подготовлен.

## Полезные замены соседей

На обучающей выборке 128 запросов teacher нашёл 75 полезных замен. Средний MRR 0,34033 → 0,44781 — **oracle с принудительным списком доноров по обучающим целям**, не достижение обученной головы и не новый test-результат.

Из teacher обучена поправка ранга 64, 100 шагов. Сила выбиралась из 0 / 0,1 / 0,2 / 0,4 на development; выбран 0,2.

- Development MRR: 0,30978 → 0,31090.
- Сырой Neighbors@10 на явно заданном пересечении 2166 хостов с локальным поведенческим эталоном: 0,15499 → 0,15134, снижение примерно 2,35%.
- Сила 0,4 давала MRR 0,31127, но Neighbors 0,14580: нарушен заранее заданный предел ухудшения 5%, вариант отклонён.
- На дне 04, 4381 запрос с допустимыми новыми целями: MRR **0,31675 → 0,31928**.
- Отдельные 95% host-bootstrap интервалы: [0,30656; 0,32592] и [0,31052; 0,32880]. Они пересекаются; статистически надёжный прирост не установлен.

Это небольшой прирост одного показателя, а source теперь изменён. Он может быть перекрыт ухудшением Behavior, Links или Identity. **Рост общего score не заявляется.** В полноценном режиме выбор идёт по полному score четырёх конфигураций; локально, без согласованных эталонов, использовался диагностический MRR с raw-Behavior guard.

## Прямой прогноз и место потери качества

Отдельно на тех же 128 запросах дня 04 (seed 31) получено:

| Прогноз | MRR |
|---|---:|
| Голосование исходного source на этих запросах | 0,33263 |
| Обучаемая модель контактов | 0,40058 |
| Популярность | 0,07320 |
| Частоты собственных прошлых контактов, включая день 03 | 0,58638 |
| Фиксированная временная эвристика | 0,60508 |

Прогноз моделью лучше голосования на этой выборке (парный query-bootstrap CI разности [0,00875; 0,12194]), но **хуже сильных простых временных baselines**. В локальной двухдневной обучающей истории мало переходов, чтобы обучить повторяемость новых относительно дня 02 контактов. Эти значения нельзя сравнивать с MRR на всей популяции как будто знаменатель одинаковый. Дополнительный прогноз использует историю строго до окна оценки, а его новые контакты определяются относительно source дня 02.

При переносе в вектор выигрыш оказался значительно меньше прямого прогноза. Это аргумент проверять одновременно temporal baseline, oracle-замены, обученную голову и настоящий top-10, а не принимать улучшение тренировочного loss за улучшение benchmark.

## Передача тимлиду

Основной следующий опыт — именно Identity-only на настоящих замороженных source plus. Для него сравнить исходные later-векторы plus, новый Ridge, устойчивые контакты и gate. Затем включать голову соседей, оценивая все четыре конфигурации на одинаковых данных. Полная история должна отделяться от development и нового закрытого test; опубликованные 14–16 — только diagnostic.

Код содержит потоковый reader, обучение, перенос поздних векторов, сохранение checkpoint и inference без обучения. Синтетический end-to-end тест проверяет полную оценку четырёх конфигураций, пять обязательных метрик, matching source-контакты и когорту. Отдельно проверены штатные ничьи и совпадение голосования с evaluation.partners, отсутствие собственного ID во входе, OOF по целым дням, замороженный source и повторное применение checkpoint.
