# Замороженный source: адаптер Identity и полезные замены соседей

Первый эксперимент меняет только векторы поздних окон. Source-файл копируется побайтно и контролируется SHA-256: при неизменных эталонах Behavior, Links, New partners и Pairs не меняются. Второй эксперимент меняет source и требует полной повторной оценки всех задач. Это код экспериментов, а не новая строка scoreboard.

## Что реализовано

- Потоковое извлечение из CSV: направленные peers, proto/dst_port, объёмы обеих сторон и шесть временных отрезков. Собственный host_id нужен только для группировки и меток обучения, не подаётся отдельным входным признаком. Кэш привязан к пути, размеру, mtime, границам и когорте; test не обрабатывается внутри runner до записи frozen_selection.json.
- Identity: переобучаемый Ridge на TF-IDF/SVD и числовых признаках; поиск профилей по редким устойчивым контактам; фиксированные смеси; gate. IDF считается по различным хостам, устойчивость контакта — по различным дням, а не по числу часов. Gate учится на полностью отложенных исторических днях, используя только более ранние дни для vocabulary/IDF/SVD/Ridge/профилей. OOF условен на переданном замороженном source: если source сам обучен на всей разрешённой истории, это не rolling-переобучение самой основы.
- Контактный прогноз: давность, число дней, повторение в тот же час, интенсивность и популярность. Параметры для исторического дня обучены только на предшествующих днях. Считаются контроли popularity, history и фиксированная временная эвристика. Первый переход без обучающих примеров использует явно заданную эвристику.
- Teacher: пробует принудительные замены в десятке; заново суммирует настоящие частоты source и неотрицательные косинусные веса, применяет штатные midrank-ничьи и цель «первый из любых правильных новых партнёров». Это oracle по *обучающим* целям, не готовый реализуемый embedding. Затем низкоранговая поправка к source учится поднимать полезного донора над удаляемым с регуляризацией исходной геометрии. При оценке используется настоящий top-10 из evaluation.partners, без ручных замен.
- Выбор силы поправки только на development; нулевой вес включён. По умолчанию запрещено терять более 5% сырого Neighbors@10 относительно контроля. В test правило не меняется.
- Когда переданы согласованные эталоны и исходные later-векторы, сравниваются: baseline, identity_only, neighbors_only, combined. Перенос поправки в позднее окно выполняется мягким поиском по исходным профилям без меток позднего хоста.
- Аудит `check_score_ceiling.py` отдельно читает публичные эталоны 70347a3 и воспроизводит оптимистичную границу 99,773301. Эти test-цели не используются обучающими runner.

## Требования к данным

Нужен CSV `host_id,emb_0,...` с фиксированными source-векторами. Для настоящего эксперимента plus передайте именно source plus: локальная проверка ниже использовала другой замороженный источник. Записи `train`, `development`, `test` в JSON имеют поля `name,day,start,end,flows` и необязательный `baseline` — файл исходного адаптера соответствующего окна. `day` должен отражать исторический порядок, числовые start/end берутся из манифестов. Окна должны не пересекаться, train заканчивается до development, development — до test.

`source_window` задаёт *настоящее окно контактов оценщика*. Оно может отличаться от самого раннего обучающего часа. Это особенно важно для 32-часовой истории: контакты New partners по-прежнему берутся из source дня 02, 11–12. Если source_window не задан, используется первая запись train.

`example.json` — шаблон с тремя train-днями и development13. Для полной истории тимлид расширяет train до дня 12 и подставляет реальные пути/границы. Укажите `source_training_end` для проверки, что исходная основа не обучалась после начала development. Test по умолчанию пуст: дни 14–16 уже опубликованы и не являются новым закрытым holdout.

## Запуск

```bash
export PT_EXPERIMENT_ROOT=/path/to/artifacts
OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 python -m experiments.frozen_adapters.run \
  --config config.json --output runs/identity01
OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 python -m experiments.frozen_adapters.run_neighbors \
  --config config.json --identity-run runs/identity01 --output runs/neighbors01
```

Для Identity используются проектные зависимости; для обучения поправки соседей дополнительно нужен torch. Сохраняются config/версии/хеши кода, SHA source, OOF-cutoff, frozen_selection, отчёты и checkpoint. `adapter.joblib` / `neighbor_head.joblib` — модели *до test*. Необязательный `refit_after_diagnostic` со своим `delivery_training_end` создаёт отдельные `delivery_*.joblib` после диагностического прогона. Ему не приписывается качество прежнего holdout.

Позднее применение без обучения:

```bash
python -m experiments.frozen_adapters.infer --source plus_source.csv \
  --checkpoint runs/identity01/adapter.joblib --flows late.csv --start START --end END --day DAY \
  --cache runs/cache --output runs/late_identity.csv
# Для совместного варианта добавить:
# --neighbor-checkpoint runs/neighbors01/neighbor_head.joblib --source-output runs/updated_source.csv
```

Без neighbor-checkpoint source сохраняется. С ним source изменяется — оценить только Identity недостаточно. Проверяются source SHA, состав/порядок хостов и исходная матрица checkpoint. Новые хосты этим source-codebook не покрываются. Для воспроизводимости checkpoint следует использовать версии окружения из protocol.json.

## Полная оценка и ограничения локальной проверки

Для полного четырёхстороннего сравнения нужны:

- `references`: отображение name окна в папку его эталонов;
- `probe_reference`: более раннее окно обучения LogisticRegression Links с тем же source;
- `score_windows`: канонические ключи текущей таблицы для дней 14–16; для нестандартного development — собственный калиброванный `neighbor_ceilings`;
- baseline late CSV и уже обученный IdentityAdapter.

Пример: `references.development13=/refs/day13`, `probe_reference=/refs/day02_validation`. **Нельзя автоматически применять потолок validation дня 02 к дню 13.** Без всех пяти обязательных метрик полный score не выдаётся. Без matching references локальный прогон сообщает только штатный New partners MRR и, если есть `behavior_features`, сырой Neighbors на явно указанном пересечении хостов. Это не общий score.

Штатный `identity_retrieval(source,later)` фактически использует source как запрос и late как галерею. В отчёте отдельно даны официальный Procrustes, прямой source→late на всех активных хостах и production-направление late→source без калибровки. Подгруппы низкой/высокой активности используют одну полную галерею, иначе сравнение было бы облегчённым.

Для локальной истории 02–04: train 02/03, development после train дня 03, целиком отложенный от адаптации день 04; затем отдельный refit на 02/03/04 для передачи. Данные уже рассматривались в прежних исследованиях, поэтому это диагностическая проверка, а не новый независимый holdout. Подробности — LOCAL_REPORT.md.

На source plus и истории 02–12 эти изменения ещё не оценены. Локальные числа нельзя прибавлять к 70,04 или считать улучшением лидера. Дополнительное сжатие 1024→256–512 также следует проверять отдельным экспериментом с переоценкой всех задач: оно меняет source и уже не является безопасной заменой одного Identity-адаптера.
