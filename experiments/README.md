# Эксперименты

Все методы на одних данных и эталонах одной командой.

```bash
python -m experiments.end_to_end --fixture --workdir runs/demo                  # самопроверка на тестовых данных
python -m experiments.end_to_end --netflow data/raw/netflow_day-02.bz2 \
    --config cfg.json --workdir runs/lanl --data-kind lanl --source-note "..." --methods all
```

Настоящие данные — по шагам в [`lanl/README.md`](lanl/README.md).

## Что получается в `<workdir>/run`

| файл | что |
|---|---|
| `scoreboard_test.md` | таблица результатов |
| `report.md`, `figures/` | отчёт с графиками |
| `results/` | все метрики по методам |
| `audit.json` | проверки валидности |

Linear probe: доступность внешних меток

Linear probe позволяет проверить, можно ли предсказать внешнее свойство хоста по его embedding с помощью простой модели, например логистической регрессии. Такими свойствами могут быть тип устройства, его роль или принадлежность к отделу.

Для корректной оценки необходимы независимые внешние метки, полученные из источника, который не использовался при построении embeddings.

В текущем наборе данных LANL нет подходящей готовой разметки хостов по ролям или типам устройств. Синтетический fixture также не содержит независимых эталонных меток этих свойств.

Создание меток на основе тех же сетевых событий, из которых строятся embeddings, привело бы к утечке данных и сделало оценку некорректной.

Поэтому при отсутствии подходящих внешних меток метрики linear probe обозначаются как недоступные (NaN). Метки не генерируются искусственно.
