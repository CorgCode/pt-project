# Поведенческий бейзлайн без портов: абляция признаков

> **СИНТЕТИКА (synthetic_fixture) — не трафик LANL.** Синтетика: у ролей генератора свои порты ПО ПОСТРОЕНИЮ, поэтому порты здесь информативны; для LANL отсюда ничего не следует.

Одинаково для всех вариантов (проверено по хешам файлов): split `test`, оцениваемых хостов 300, одни и те же замороженные эталоны, обучение только на окне `train`, политика когорты `train_only`.

## Стандартный эталон: полный профиль против профиля без портов

| метрика | полный | без портов | полный − без портов (парный 95% CI) |
|---|---|---|---|
| kNN Consistency@10 | 0.280 | 0.272 | +0.008 [-0.000, +0.016] |
| nDCG@10 | 0.264 | 0.261 | нет пары |
| Link ROC-AUC (cosine) | 0.478 | 0.457 | +0.021 [+0.015, +0.027] * |
| Link ROC-AUC (learned) | 0.668 | 0.656 | нет пары |
| Pair ROC-AUC | 0.907 | 0.885 | +0.022 [+0.006, +0.042] * |
| Triplet accuracy | 0.918 | 0.887 | +0.031 [+0.000, +0.072] |

`*` — парный интервал не содержит 0. Хосты пересэмплируются одновременно для обоих вариантов (для пар, связей и троек — бутстреп по хостам); интервалы описывают только выбор оцениваемых элементов.

## Диагностика: эталон, пересобранный БЕЗ портов (только анализ)

_эталон пересобран по тому же целевому окну БЕЗ блока портов; другой отпечаток, с таблицей результатов НЕ сравнивается_

| kNN Consistency@k | полный | без портов | случайно |
|---|---|---|---|
| @5 | 0.192 | 0.191 | 0.017 |
| @10 | 0.265 | 0.269 | 0.033 |
| @20 | 0.398 | 0.395 | 0.067 |

Парная разность «полный − без портов» при k=10: -0.004 [-0.013, +0.004]. Совпадение соседей эталона без портов с соседями стандартного: Consistency@10 = 0.770 (случайно 0.033).

## Что это значит для методологии

1. **Стандартный поведенческий эталон содержит блок портов** (около 18% квадрата веса профиля). Поэтому полный бейзлайн делит эту информацию с эталоном **по построению**; вариант без портов это пересечение убирает. Разница на kNN — это пересечение информации, а не качество представления (здесь парная разность kNN@10 = +0.008).
2. **Порты есть только в kNN-эталоне.** Эталоны пар и троек по общим собеседникам и кандидаты будущих связей строятся из собеседников, поэтому абляция портов на них показывает, сколько *идентичность сервиса* добавляет к структурному и прогнозному сигналу, а не пересечение с эталоном.
3. **Диагностика без портов показывает остаток.** Если разность «полный − без портов» исчезает, когда порты убраны и из эталона, то разность на стандартном эталоне была пересечением по портам; если остаётся — её дают другие блоки. Диагностика не является эталоном таблицы результатов, смешивать их нельзя.
4. **Что такое порты в LANL NetFlow.** Известные порты сохранены, остальные обезличены в стабильные `PortNNNN`, поэтому блок портов отчасти работает как идентификатор сервиса. Профиль без портов проверяет, опирается ли метод на сервис или на форму трафика (объём, направление, собеседники, протоколы, время суток).
5. **Таблица результатов не меняется.** Стандартные эталоны, хосты и окна те же; варианты без портов — дополнительные строки (`--port-free-baselines`). Каждый блок нормируется отдельно, поэтому оставшиеся колонки совпадают с полным профилем.
6. **Ограничения.** Одна пара окон, одна когорта, нет меток ролей; абляция говорит, какую информацию поощряет *приближение*, а не какая информация определяет роли.
