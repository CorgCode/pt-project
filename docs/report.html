Главное

  • Лучший метод — hybrid_tfidf, score 45,3 из 100. Лучший одиночный — behavioral, 40,4.
  • Графовые методы в одиночку — 3,8–23,8, но в гибриде с behavioral дают прирост.
  • Граф host–service вместо host–host: node2vec 17,6 → 23,8.
  • Нужно решение: веса задач в score (сейчас равные; предложение — Behavior и Identity × 2).

Задача и данные

Для каждого хоста получить вектор по сетевому трафику: хосты с похожим поведением — рядом, тот же хост узнаётся через время. Учимся только на train-окне, всё оцениваем на более позднем test-окне.

Данные: LANL Unified Host and Network 2017, NetFlow, день 02 Записей: 115 949 436 Окна: train 60 мин → validation → test 30 мин Хостов в оценке: 2 242

Эталоны для метрик строятся из логов test-окна, без эмбеддингов (pipeline/reference.py). Подбор параметров — только на validation.

88% связей test уже были в train (правило «уже общались» — AUC 0,939), поэтому есть new-partner MRR.

Как считается score

1. каждая метрика: s = 100 · (v − случайный) / (1 − случайный), обрезка в [0, 100]
2. задача: среднее геометрическое её метрик
3. score: среднее геометрическое 4 задач, значения ниже 1 считаются за 1

Пример, hybrid_tfidf: Behavior 23 · Future links 39 · Shared partners 88 · Identity 52 → score 45,3.

Почему так

  • Нормировка к случайному уровню: у метрик разная шкала.
  • Среднее по задачам, а не по метрикам: две метрики про связи не весят вдвое больше.
  • Геометрическое: провал в одной задаче не скрыть хорошими AUC.

Проверки

  • Порог 0,1–2 вместо 1 — порядок тот же.
  • Шум в пределах 95% интервалов — лидер первый в 96% случаев (простое среднее — 89%).
  • 5 вариантов весов — лидер везде тот же.
