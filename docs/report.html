Задача и данные

Для каждого хоста получить вектор по сетевому трафику: хосты с похожим поведением — рядом, тот же хост узнаётся через время. Учимся только на train-окне, всё оцениваем на более позднем test-окне.

Данные: LANL Unified Host and Network 2017, NetFlow, день 02 Записей: 115 949 436 Окна: train 60 мин → validation → test 30 мин Хостов в оценке: 2 242

Эталоны для метрик строятся из логов test-окна, без эмбеддингов (pipeline/reference.py). Подбор параметров — только на validation.

Без эмбеддинга правило «пара уже общалась» даёт link ROC-AUC 0,939: 88% связей test уже были в train. Поэтому в задаче Future links есть и new-partner MRR — она про новых собеседников.

Как считается score

1. каждая метрика: s = 100 · (v − случайный) / (1 − случайный), обрезка в [0, 100]
2. задача: среднее геометрическое её метрик
3. score: среднее геометрическое 4 задач, значения ниже 1 считаются за 1

Пример, hybrid_services: Behavior 26 · Future links 42 · Shared partners 91 · Identity 16 → score 35,4.

Почему так

  • Нормировка к случайному уровню. У метрик разная шкала: AUC 0,75 — это слабо, MRR 0,23 — хорошо. После нормировки 0 — случайно, 100 — идеал.
  • Задачи, а не метрики. Две метрики про связи не должны весить вдвое больше одной про узнаваемость.
  • Среднее геометрическое. Считается рост во сколько раз: 8 → 16 весит как 45 → 90. Провал в одной задаче не скрыть хорошими AUC.
  • Score не зависит от других методов. Новый метод не меняет баллы остальных.

Проверки устойчивости

  • Порог «ниже 1 считать за 1» от 0,1 до 2 — порядок методов не меняется.
  • Шум в метриках в пределах их 95% интервалов: лидер остаётся первым в 96% случаев (у простого среднего — 89%).
  • 5 вариантов весов задач: лидер везде hybrid_services, лучший одиночный метод — behavioral.
  • Сейчас веса задач равные. Предложение: Behavior и Identity × 2 — нужно ваше решение.
