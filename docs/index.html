Исследовательский проект PT-05 · МФТИ · Positive Technologies

Векторные представления хостов по сетевому трафику

Мы проверяем, можно ли по журналам сетевых потоков (NetFlow) описать каждый хост короткой числовой строкой так, чтобы похожие по поведению хосты оказывались рядом, а одному и тому же хосту в соседних временных окнах соответствовали близкие векторы.

Данные. Все числа и графики — первый прогон на настоящих данных LANL: один день, train — 1 час, test — 30 минут, оценено 2242 активных хоста (#60). Источник заявлен (форма LANL), пайплайном не проверяется.

Цель

Научиться по логам сети строить для каждого хоста вектор, по которому можно:

  • находить хосты с похожим поведением;
  • видеть группы и роли хостов без ручной разметки;
  • замечать подозрительные изменения поведения;
  • объяснять, почему хосты считаются похожими.

Исследовательский вопрос

Какие способы построения эмбеддингов хостов — простые поведенческие признаки или методы на графе коммуникаций — лучше сохраняют сходство хостов и устойчивы во времени, если сравнивать их по одним и тем же правилам.

Что такое эмбеддинг хоста

Это вектор из нескольких десятков чисел (emb_0 … emb_d), который метод строит для каждого хоста. Расстояние между векторами должно отражать различие в поведении: с кем хост общается, как часто, по каким протоколам.

Зачем это на практике

Такие векторы позволяют искать похожие хосты, группировать их по ролям, находить аномальные отклонения и отслеживать один и тот же хост при смене адреса. Для этого нужен честный способ сравнить методы между собой — это и есть основной результат проекта: единый конвейер и единые метрики.

CГрафовые методы

Все методы получают один и тот же граф коммуникаций обучающего окна и возвращают таблицу host_id, emb_0 … emb_d. Три метода из предложенного списка описаны подробнее.

node2vec

в предложенной тройкекод в main

Идея. Случайные блуждания по графу превращаются в «предложения» из хостов; модель skip-gram учит вектора так, чтобы хосты, встречающиеся рядом в блужданиях, были близки. Параметры p и q смещают обход к ближайшему окружению или к дальним областям.

Отличие. От DeepWalk — управляемое смещение обхода и отрицательная выборка вместо иерархического softmax.

Вход
взвешенный граф «хост — хост» обучающего окна
Выход
CSV: host_id, emb_* — по строке на хост когорты
Код
node2vec.py · описание

struc2vec

в предложенной тройкекод в main

Идея. Близкими считаются хосты с похожей ролью, даже если они далеки друг от друга в сети: сравниваются последовательности степеней соседей на разных расстояниях (динамическое выравнивание), по ним строится вспомогательный многослойный граф и по нему — обходы.

Отличие. DeepWalk и node2vec кодируют «кто рядом», struc2vec — «как устроено окружение». Метод дороже по вычислениям.

Вход
граф обучающего окна (используются степени и структура окрестностей)
Выход
CSV: host_id, emb_*
Код
struc2vec.py · описание

GraphSAGE

в предложенной тройкекод в main

Идея. Вектор хоста вычисляется как функция его признаков и усреднённых признаков соседей. Обучение без учителя: соседние по обходам хосты сближаются, случайные — отдаляются.

Отличие. Метод индуктивный: обученную функцию можно применить к хосту или окну, которых не было при обучении, поэтому координаты общие для разных окон — важно для сравнения во времени.

Вход
граф и признаки хостов обучающего окна
Выход
CSV: host_id, emb_*; общая система координат
Код
graphsage.py · описание

DeepWalk

код в main

Равномерные случайные блуждания + skip-gram с иерархическим softmax. Простейший метод семейства; служит опорой для сравнения с node2vec. deepwalk.py

RolX

код в main

Рекурсивные структурные признаки хоста (ReFeX) раскладываются неотрицательной факторизацией на «роли»; вектор хоста — его принадлежность ролям. Хорошо интерпретируется. rolx.py · описание

DБазовые модели

Базовая модель нужна, чтобы сложный метод можно было сравнить с простым. Если граф-метод не лучше поведенческих признаков, его сложность не оправдана. Все базовые модели обучаются только на обучающем окне — как и графовые методы.

Поведенческий профиль в main

Стандартизованные признаки хоста: объём трафика, степень, направление, порты, протоколы, распределение по часам. Варианты: без снижения размерности, PCA, SVD.

Включает блок портов, поэтому частично пересекается с эталоном сходства — это учтено в аудите пересечения информации.

Спектральное вложение графа в main

Собственные векторы нормированной матрицы смежности графа коммуникаций (веса — log1p числа потоков). Использует только структуру связей, без признаков хоста.

Для каждого окна считается отдельно, поэтому векторы разных окон нельзя сравнивать без выравнивания.

Вариант без портов в main влит без ревью — pull request #62 проверяет, сколько качества дают сами порты (issue #43). На LANL её пока не запускали (флаг --port-free-baselines).

Дополнительно в оценке участвуют два служебных ориентира: случайные векторы (нижняя граница) и «потолок эталона» — модель с утечкой, не являющаяся методом.

EЭкспериментальные результаты

Графики читаются из файла data/results.json (коммит —). Данные — первый прогон на LANL (results/lanl_day02): все пять графовых методов и бейзлайны на одних и тех же хостах, окнах и эталонах; собирает python docs/build_data.py. Общая таблица результатов команды (с лидером и интервалами) — scoreboard/README.md.

1. Сохранение ближайших соседей (Neighborhood Consistency@k)

LANL · ДЕНЬ 02 · ИСТОЧНИК ЗАЯВЛЕНтестовое окно

Что измеряется. Доля из k ближайших соседей хоста в пространстве эмбеддингов, которые входят и в список k соседей по эталону поведения.

Как читать. Правее — лучше; 1 означает полное совпадение. Три маркера — k = 5, 10, 20. Рост с k ожидаем: большая выборка соседей легче пересекается.

Что показывают результаты. Лучше всех behavioral (0,27) — эталон построен из похожих признаков. Графовые методы — 0,06–0,13: они смотрят на структуру связей, а не на объём и порты. Случайные векторы — 0,004.

Чего вывести нельзя. Что behavioral «лучше»: он и эталон построены из одних признаков, поэтому совпадение частично предопределено.

2. Прогноз будущих связей (ROC-AUC)

LANL · ДЕНЬ 02 · ИСТОЧНИК ЗАЯВЛЕНтестовое окно

Что измеряется. Насколько хорошо по эмбеддингам обучающего окна можно отличить пары хостов, которые свяжутся в будущем, от тех, что не свяжутся.

Как читать. 0,5 — случайное угадывание; ближе к 1 — лучше. Три маркера: косинусная близость, обученный классификатор, только новые связи (без повторов уже виденных).

Что показывают результаты. По косинусу связи предсказывают только DeepWalk (0,78) и node2vec (0,72). У остальных косинус ниже 0,5: в LANL связаны клиент и сервер, а они непохожи. Обученный классификатор достаёт сигнал из всех: behavioral и спектральный граф — 0,98.

Чего вывести нельзя. 88% завтрашних связей уже есть сегодня, и правило «пара уже общалась» даёт 0,94. Честнее смотреть на «только новые связи»: там лучше всех DeepWalk (0,65), остальные около 0,5.

3. Различение похожих и непохожих пар (ROC-AUC пар)

LANL · ДЕНЬ 02 · ИСТОЧНИК ЗАЯВЛЕНтестовое окно

Что измеряется. Различает ли расстояние между векторами пары, которые эталон считает похожими, от явно непохожих.

Как читать. 0,5 — случайно, 1 — идеально. Пунктирный контур — потолок эталона, модель с утечкой.

Что показывают результаты. Графовые методы и behavioral отделяют похожие пары почти идеально (0,95–0,98). struc2vec — 0,53: структурная роль и общие собеседники — разные вещи.

Чего вывести нельзя. Оцениваются только «крайние» пары (сходство ≥ порога или ровно 0); спорные исключены. Графовые методы и эталон пар построены из одних связей — высокий результат частично предопределён.

4. Устойчивость идентичности хоста во времени

LANL · ДЕНЬ 02 · ИСТОЧНИК ЗАЯВЛЕНtop-1, оба окна

Что измеряется. Доля хостов, ближайший вектор которых в следующем окне принадлежит тому же хосту (top-1).

Как читать. Пунктир — случайное угадывание (1/число хостов). Второй маркер — после ортогонального выравнивания Прокруста, когда координаты окон подгоняются друг к другу.

Что показывают результаты. Узнать тот же хост через полчаса трудно всем: лучше всех behavioral — 10% с первой попытки при случайном уровне 0,1%. У методов, обученных на каждом окне заново, без выравнивания почти 0.

Чего вывести нельзя. Окна по 30 минут — короткие: поведение хоста за полчаса заметно меняется само (соседи совпадают лишь на 0,31).

5. Проекция пространства эмбеддингов (PCA)

LANL · ДЕНЬ 02 · ИСТОЧНИК ЗАЯВЛЕНповеденческий профиль, 2242 хоста

Что измеряется. Первые две главные компоненты векторов; цвет точки — доля совпавших соседей этого хоста (средняя по хостам: ).

Как читать. Близкие точки — близкие хосты. Тёмные точки — хосты, чьи соседи совпали с эталоном; светлые — нет.

Что показывают результаты. Наглядно, где метод согласуется с эталоном, а где нет. Наведите курсор на точку — виден идентификатор хоста.

Чего вывести нельзя. Двумерная проекция искажает расстояния; по ней нельзя судить о качестве метода количественно.

6. Общая таблица команды

LANL · ДЕНЬ 02 · ИСТОЧНИК ЗАЯВЛЕНобщий балл, test
LANL · ДЕНЬ 02 · ИСТОЧНИК ЗАЯВЛЕНвсе методы

Что измеряется. Каждая метрика переводится в 0–100: 0 — как у случайных векторов, 100 — идеал. Метрики собраны в четыре задачи: поведение, будущие связи, общие собеседники, узнаваемость. Балл — среднее геометрическое по задачам.

Почему не простое среднее. Каждая задача весит одинаково, рост в 2 раза в трудной колонке весит как рост в 2 раза в лёгкой, а провал в одной задаче не скрыть хорошими AUC.

Как читать. «разм.» — длина вектора: при разной размерности сравнение не совсем честное. Жирным — лучшее в колонке.

Что показывают результаты. Гибриды впереди: только они хороши во всех четырёх задачах. Графовые методы сами по себе почти не узнают хосты, поэтому стоят ниже, а struc2vec — почти на случайном уровне.

Чего вывести нельзя. 100 недостижимо даже в принципе: поведение хоста за полчаса меняется само. Балл годится для сравнения методов, а не как «процент готовности».

Свой метод добавляется в таблицу коммитом — scoreboard.

  • Сравнимые эталоны. Эталоны сходства строятся один раз и замораживаются; каждый метод оценивается против одних и тех же эталонов.
  • Защита от утечки. Когорта и обучение определяются только по обучающему окну; пересечение информации методов и эталонов проверяется отдельным аудитом (методология).
  • Происхождение данных. Каждый результат помечен: заявленный LANL, непроверенные данные или тестовая синтетика; метки «проверено» нет.
